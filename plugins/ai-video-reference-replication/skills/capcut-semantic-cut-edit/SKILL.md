## 공유 플러그인 실행 경로

이 문서가 들어 있는 `skills`의 상위 폴더를 `PLUGIN_ROOT`로 확인하고, 먼저 `../../references/recipient-runtime.md`를 읽는다. `${PLUGIN_ROOT}`는 현재 설치된 이 플러그인의 절대 경로로, `${VIDEO_PRODUCT_LIBRARY_ROOT}`와 `${CAPCUT_AUTOMATION_ROOT}`는 수신자 환경의 경로로 해석한다. 하위 스킬은 이 플러그인 안의 형제 폴더를 우선 사용한다. 플러그인 제작·수정·공유 요청은 영상 제작 인터뷰나 유료 생성, 앱 종료를 시작하지 않는다.


# 문맥별 CapCut 컷편집

`capcut-cut-edit`의 **대본 + 클린본 + 사용자 음성** 모드다. 구조는 **기존 공통 컷편집 + 제품 종류별 화면 연출 프로필**이다. 제품 종류는 클린본에서 무엇을 골라 어떻게 보여줄지만 바꾸며 자막·호흡·무음·싱크·공통 컷 기준을 바꾸지 않는다. 별도 호출을 사용자에게 요구하지 않는다. 모델이 실제 장면과 문맥을 판단하고, 기존 도구가 시간·구간·확대·소스·저장을 검사한다. 모델 가중치 학습이나 자동 영상 인식 엔진이 아니다.

## 먼저 읽을 것

1. [공통 컷·음성·자막 기준](../capcut-cut-edit/SKILL.md). 아래 모드에서는 그 문서의 **기존 영상 순서 유지 / 확대·크롭 금지** 대신 이 문서의 장면 선택·프레이밍을 쓴다. 공통 음성·자막 규칙은 그대로 적용한다. 다시 자신에게 라우팅하지 않는다.
2. [제품 종류 인터뷰와 화면 전용 프로필](references/visual-direction.md). 직접 이 스킬로 시작해도 제품 종류 접수가 먼저다. 종류가 미선택이면 하나만 질문하고 응답을 기다린다.
3. 종류가 확정된 뒤 [분야별 선택 기준](references/categories.md)과 선택한 분야의 프로필만 읽는다. 식품이면 `food-nuttybutty-01/visual-v2`의 화면 규칙을 적용한다.
4. 실제 분석·저장 전에 [실행과 계획 형식](references/execution.md)을 전부 읽는다.

## 입력과 범위

- 첫 접수는 제품 종류 선택이다: **1. 건기식 / 2. 뷰티 / 3. 식품 / 4. 그외**. 이번 요청·이번 작업 답변의 직접 선택만 인정하고, 호두정과 같은 제품명이나 예전 업체 기록으로 자동 선택하지 않는다. 응답 전에는 프로필 선택·자료 분석·타임라인 준비를 시작하지 않는다. 이미 이번 작업에서 선택했다면 다시 묻지 않는다.
- 상위 제작 인터뷰의 `production_intake.capcut.category`와 답변 원문은 이 접수의 완료 근거로 인정한다. `2` 같은 숫자만 재해석하지 말고 `beauty` 등 정규화된 값을 쓴다. 비율·TTS 방식·편집 요청·폰트도 이미 확정됐다면 다시 묻지 않는다. `other`는 이번 제품의 실제 사용·조작·시연을 따르는 일반 화면 원칙으로 처리한다.
- 종류 확인 후 업체·제품과 대본·이번 제품 클린본·사용자 음성을 받는다. 제품·음성이 실제 녹음인지 TTS인지, 저장할 기존 업체 프로젝트 중 실제 누락·중복된 값만 확인한다. **기준 타임라인은 입력 항목이 아니다.** 저장된 화면 규칙을 다시 배우기 위해 매번 원본 타임라인을 찾거나 열지 않는다.
- 새 편집 가능한 타임라인 1개와 그 고유 이름은 기본 산출물이다. “새 타임라인으로 만들어줘”라는 문구나 이름 지정이 없어도 이 방식으로 만든다. 프로젝트의 기존 타임라인 수가 여러 개라는 사실만으로 기준 선택을 묻지 않는다.
- 현재 요청이 스킬 설명/수정이면 그 작업만 한다. 입력 영상을 찾아 임의 편집하지 않는다.
- 이 모드는 기본적으로 화면 컷·음성 컷·기본 자막을 포함한다. 자막 제외 등 명시적 변경은 존중하되 현재 저장기가 지원하지 않는 예외는 임의 구현·우회하지 않고 그 제한을 알린다.
- 기본 1080×1920, 9:16. FPS는 대상 작업의 값을 쓰며 지정이 없으면 30fps다. 원본 미디어 자체는 변환하지 않는다.
- 제품 사실은 사용자의 대본을 따른다. 다른 업체/제품의 사실·영상·실행 경로를 가져오지 않는다. 대본 재작성, 새 음성/영상 생성, 효과음·BGM·효과·전환·이미지 추가, 스타일 모사, 배리에이션은 하지 않는다.

## 장면 판단

1. 공통 컷편집 기준으로 정한 대본 의미 단위와 최종 발화 시각을 받아 각 단위의 **표현 의도**를 적는다. 분야 프로필은 그 구간에 넣을 화면을 고르는 데만 쓴다. 표시 자막을 나눈 횟수만큼 영상 컷을 만들지 않는다.
2. 이번에 제공받은 클린본을 실제로 살펴보고 후보 구간을 찾는다. 파일명·썸네일 한 장·예전 영상 순서로 장면을 추정하지 않는다. 긴 파일 안에서 장면이 바뀌면 구간을 나눈다.
3. 문맥에 직접 맞는 같은 제품의 행동·제품 디테일·공정 장면을 우선한다. 없으면 **먹는 제품은 먹는 장면, 바르는 제품은 바르는 장면**, 그외는 같은 제품의 실제 사용·조작·시연 장면 중 표현이 잘되는 장면으로 채운다. `selection.mode=fallback`과 대체 이유를 남긴다. 먹는 화면을 실제 공정 증거라고 적거나 관련 없는 자료를 일반 시연으로 포장하지 않는다.
4. 제품, 손/입, 도포 부위 등 문장에 필요한 대상이 중앙에서 적절한 크기로 보이게 한다. 모든 장면에 같은 제품 점유율을 강제하지 않는다. 공정은 필요한 작업 맥락도 보여준다.
5. 크롭·위치 보정은 허용하되 **CapCut 확대는 150% 미만**이다. 150%는 불가다. 도구는 9:16 최대 내접 영역을 기본 크롭으로 잡고 100% 이상·150% 미만의 확대와 이동을 적용한다. 작은 추가 크롭으로 확대 제한을 우회하지 않는다. 허용 범위에서 표현이 안 되면 다른 후보를 고른다.
6. 실제 사용할 구간과 보정값으로 시작·중간·끝 확인 이미지를 만들고 직접 본다. `review.note`는 실제 관찰 뒤에만 채운다. 대상이 잘리거나 가려지면 수정하고 다시 추출한다. 정지 이미지로 불명확한 행동은 추가 프레임/해당 소스 구간 확인으로 보완한다.

## 구간 재사용

- 기준은 **원본의 실제 시간 구간**이다. 같은 파일 안에서도 겹치지 않는 구간은 별개다.
- 겹치는 구간은 최대 2회. 첫 사용 전체가 완성 영상 앞 1/3 안에 있고, 두 번째 사용 전체가 뒤 1/3 안에 있을 때만 허용한다. 앞·중간에서 재등장시키지 않는다. 경계를 걸치면 다른 구간을 고른다.
- 파일 이름을 바꾸거나 복사해도 같은 내용이면 같은 소스다. 일부만 겹치는 재사용도 검사한다.
- 앞/중간/뒤는 **이번 최종 음성 기준 완성 영상 1개**를 3등분한다. 여러 배리에이션을 붙인 타임라인 전체 길이로 계산하지 않는다.
- 연속된 같은 원본의 기술적 분할은 하나의 의미 컷으로 정리한다. 루프·정지화면·배속으로 분량을 채우지 않는다. 유효한 대체 장면도 없으면 공통 기준의 선언된 섹션 꼬리 공백만 허용하고 결과에 분명히 표시한다. 의미 섹션 전체가 비면 추가 소스가 필요하다.

## 실행 순서

모든 단계의 음성·쉼·자막 타이밍은 [전역 컷편집 기본값](../capcut-cut-edit/SKILL.md)을 따른다. 각 자막의 실제 첫 발음 상승을 개별 확인하고 짧은 불필요한 쉼·영상 컷 0프레임 일치를 적용한다. 일반적인 `컷편집 해줘`에 제품 장면의 새 선택·배치 요청이 없다면 공통 스킬의 일반 컷편집으로 연결하며 이 모드의 제품 종류 인터뷰를 시작하지 않는다.

1. 제품 종류 응답을 받은 뒤 해당 **화면 프로필**과 이번 입력을 불러오고 정확한 **저장 프로젝트**를 확인한다. `resolve-project`로 그 프로젝트의 저장 형식을 자동 확인한다. 반환된 `source_id`는 기술 정보 연결용이지 화면 학습 기준 선택이 아니다. 승인 사례의 경로/미디어를 다른 업체의 저장 대상/소스로 사용하지 않는다.
2. `inventory` → `init-plan` → `analyze-voice`. 무음은 후보일 뿐이다. 실제 단어·문맥·의도적 쉼을 확인한 뒤 원본 음성 컷만 계획한다. 새로운 전사 모델 다운로드/외부 전송을 임의로 하지 않는다.
3. `prepare-audio`로 최종 확인 음성을 만든다. 그 음성에서 실제 발화와 파형을 확인해 자막 첫소리와 의미 컷을 정한다. 옛 시간, 글자 수 비례, 구간 균등 분배로 발화 시점을 꾸미지 않는다. 음성 컷이 바뀌면 확인 음성과 타이밍도 다시 만든다.
   - 현재 저장기는 최종 음성의 첫 발화가 0번 프레임 안에서 시작하는 구성을 지원한다. 불필요한 시작 무음만 실제 청취 후 정리할 수 있다. 의도적인 시작 쉼을 남겨 첫 발화가 뒤 프레임에서 시작해야 하면 `LEADING_SPEECH_ALIGNMENT_REQUIRED`로 그 제한을 보고한다. 검사를 통과하려고 쉼을 삭제하거나 자막/발화 시점을 앞당기지 않는다.
4. 의미별 원본 구간을 선택·보정하고 `contact-sheet`로 실제 장면을 확인한다. 모든 클린본 원음은 0, 사용자 음성은 원속·원피치다.
5. 한 줄 자막·문법·소수점 등 실제 문구를 확인한다. 인접 자막의 끝/시작은 같은 프레임, 새 의미 첫 자막과 영상 컷은 같은 프레임이다. `validate`는 실제 폰트 폭, 음성 컷의 PCM, 선택 프레임을 원본에서 다시 비교한다. **의미 적합성·한국어 문법·실제 발화 onset 판단은 모델의 별도 검토**이며 자동 검사로 대체되지 않는다.
6. 안정된 입력으로 `bind` → 프로젝트 밖 `stage`를 만든다. 일반 호출에서는 `--source-id`, `--source-name`, `--destination-name`을 생략한다. 도구가 저장용 연결과 새 이름을 정한다. CapCut이 켜져 있으면 여기까지 준비할 수 있으나 라이브 저장은 안 한다. 프로젝트 파일이 바뀌면 정상 종료 후 새 바인딩/준비본을 만든다.
7. CapCut이 실행 중이면 [공통 자동 저장·정상 종료 절차](../capcut-cut-edit/SKILL.md#실행-중인-capcut의-자동-저장정상-종료)로 현재 작업을 저장하고 직접 정상 종료한다. 사용자에게 종료나 종료 승인을 요청하지 않는다. 종료·잠금 해제 후 최신 입력을 재확인하고 `install` → `verify`. 새 타임라인 1개만 추가하고 기존 타임라인·원본·선택된 메인 타임라인을 유지한다. 강제 종료/잠금 삭제/레거시 우회/기존 파일 덮어쓰기는 금지다.

## 결과와 학습 경계

`staged_not_registered`는 준비본이며 편집 완료가 아니다. `registered_pending_native_playback`은 기존 프로젝트에 새 편집 가능한 타임라인을 추가하고 파일을 다시 읽어 검사한 상태다. **CapCut에서 실제 재생·청취·화면 렌더를 확인했다는 뜻은 아니다.** 공통 절차의 저장·정상 종료 제어 외에 앱 재열기/GUI 편집/MP4 내보내기를 자동으로 추가하지 않는다.

최종 보고에는 새 타임라인 이름/위치, 길이, 대체/재사용/공백, 실제 검증 범위를 짧게 적는다. 실제 재생 확인이 없으면 남은 확인으로 표시한다. 실행 도중 중단되면 남은 새 폴더와 색인 백업 위치를 알리고, 자동 삭제나 승인 조작으로 복구하지 않는다.

현재 승인 타임라인에서 추출한 화면 사례는 식품 1개뿐이다. 뷰티/건기식은 사용자 지정 화면 원칙을 적용하며 승인 타임라인 학습이 끝났다고 말하지 않는다. 사용자가 새 사례의 학습을 요청하면 [화면 전용 학습 범위](references/visual-direction.md)에 맞춰 해당 분야 자료만 갱신한다. 이 과정에서 공통 스킬의 자막·음성·호흡·싱크·컷 기준이나 실행 코드를 수정하지 않는다.
