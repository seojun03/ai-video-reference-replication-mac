# 입력 폴더 규칙

## 권장 구조

업체와 작업 단위로 원본을 분리한다.

```text
${VIDEO_PRODUCT_LIBRARY_ROOT}/
└── 업체명/
    ├── 제품명/
    │   ├── 제품 정보/
    │   ├── 제품 마스터 이미지/
    │   ├── 상세페이지 원본/
    │   ├── 대본/
    │   └── 생성 결과물/
    ├── _knowledge/
    │   └── products/제품명/
    └── 작업명/
        ├── input/
        │   ├── 대본.txt
        │   ├── project_manifest.json
        │   ├── 영상/
        │   ├── 음성/
        │   ├── 이미지/
        │   ├── 효과음/
        │   └── 레퍼런스/
        └── output/
```

`${VIDEO_PRODUCT_LIBRARY_ROOT}`를 새 작업의 기본 업체 루트로 사용한다. 사용자가 현재 작업에 다른 루트를 명시한 경우에만 재정의한다. 기존 `${VIDEO_PRODUCT_LIBRARY_ROOT}` 아래 자료는 자동으로 이동하거나 재구성하지 않는다.

CapCut 프로젝트 폴더에는 직접 원본을 넣지 않는다. 자동화 엔진이 새 초안을 만들면서 필요한 미디어를 초안 내부 `media` 폴더에 하드 링크하며, 다른 디스크라 하드 링크할 수 없는 파일만 복사한다.

## 파일 배치

- `대본.txt`: 실제로 사용할 최종 대본 한 개를 둔다.
- `영상/`: 클린본/B-roll 또는 자동 컷편집할 원본 영상을 둔다.
- `음성/`: 별도 보이스오버 파일을 발화 단위로 둔다.
- `이미지/`: 제품·인물·참고 이미지를 둔다. v0.1에서는 자동 배치하지 않는다.
- `효과음/`: 사용자가 지정한 효과음 라이브러리다. `긍정/`, `현타/`, `전환/` 같은 기존 하위 폴더 분류를 그대로 보존한다. 비어 있어도 다른 편집은 계속한다.
- `레퍼런스/`: 이번 작업에서 따라갈 편집 스타일의 영상을 둔다. 분석 결과는 `output/reference_analysis/`에 새로 만들고 이전 작업 결과와 섞지 않는다.
- `project_manifest.json`: 보이스오버 몽타주에서만 필수다.

업체별 제품 자료를 이어 쓰는 작업은 원본 제품 폴더를 재구성하지 않는다. `manage_product_context.py sync`가 제품 문서·제품 마스터·상세페이지 원본·최근 대본을 읽고 업체의 `_knowledge/products/<제품>/`에 파생 색인만 만든다. 상세 계약은 [제품 컨텍스트와 피드백 누적 워크플로우](product-context-feedback-workflow.md)를 따른다.

## 이름 규칙

- 업체명과 작업명은 사람이 읽을 수 있는 이름으로 유지한다.
- 음성 파일명에는 순서 또는 고유 타임스탬프를 넣는다.
- 같은 문장의 후보 녹음이 여러 개면 파일을 삭제하지 말고 매니페스트에서 선택본만 참조한다.
- 기본 `logical_caption` 보이스오버 작업은 파일 정렬 인덱스 대신 `video_assignments[].match`에 정확히 한 파일만 찾는 고유 파일명 조각을 쓴다. 파일을 추가한 뒤에는 모든 match가 여전히 1개인지 입력 검사로 확인한다.
- 영상 소스를 넣은 뒤 파일당 여러 시점과 실제 사용할 구간을 확인해 대본 역할 태그와 추천 `source_start`를 기록한다. 파일명만으로 장면 의미를 확정하지 않는다.
- 효과음은 자동화를 위해 이름을 바꿀 필요가 없다. 파일명과 상위 폴더명을 색인 태그의 근거로 사용하며 원본을 수정하지 않는다.

## 기존 파일이 이미 있을 때

기존 폴더를 무리하게 재구성하지 않는다. `run_capcut_automation.py inspect`로 파일을 찾고, 매니페스트의 `video_dir`과 `audio_dir`을 실제 상대 경로에 맞춘다.
