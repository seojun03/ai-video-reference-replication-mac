# 대본 표현 정보 인터뷰

## 목표

대본마다 달라지는 논리와 설득 순서를 먼저 해석하고, 제품을 영상으로 자연스럽게 표현하는 데 실제로 필요한 정보만 사용자에게 질문한다. 질문 수를 늘려 완전한 제품 명세를 수집하는 것이 목적이 아니다. 답에 따라 장면의 피사체, 동작, 물성, 공간, 변화 과정, 카메라 구도 또는 최종 상태가 달라질 때만 질문한다.

이 스킬은 인터뷰와 시각 정보 정리까지만 수행한다. 사용자가 함께 요청하지 않았다면 전체 스토리보드, 이미지 프롬프트, 영상 생성, 비용 확인 또는 게시 작업으로 넘어가지 않는다.

## `finalized_script_detail` 상위 워크플로 프로필

`ai-video-reference-replication`이 `interview_profile: "finalized_script_detail"`로 호출하면 상위 스킬의 `${PLUGIN_ROOT}/skills/ai-video-reference-replication/references/finalized-script-visual-detail-interview.md`를 적용한다. 이 프로필에서만 다음 예외를 허용한다.

- 사용자가 확정한 대본 뒤 한 번의 통합 질문 턴에서 최대 6개의 묶음 질문을 한다.
- 시각 기획의 의미 단위, 컷 수 또는 CTA 구도를 바꾸는 대본 오탈자·동음이의어·발음 교정, 목표 낭독 시간, 레퍼런스형 배너·자막 여부를 물을 수 있다.
- 사용자가 표현 강도나 세부 설정을 임의로 정하지 말라고 하면 미확정 고영향 변수에 기본값을 선택하지 않고 답변 전까지 `ready_for_visual_planning: false`로 유지한다.

이 예외 외에는 질문 관련성, 이미 답한 값 재질문 금지, 외부 검증 금지, 인터뷰 후 생성 작업 금지 규칙을 그대로 유지한다.

## 시작 조건

1. 현재 대화에서 사용자가 직접 제공하거나 지정한 대본, 제품 정보, 이미지, 영상, 링크와 선택 사항만 확인한다.
2. 대본이 없으면 대본만 요청하고 그 턴을 끝낸다.
3. 대본이 있으면 제품명, 카테고리 또는 사용 장면을 대본에서 먼저 추론한다. 추론할 수 있는 내용을 다시 묻지 않는다.
4. 사용자가 지정한 자료만 검사한다. 사용자가 검색이나 검증을 요청하지 않았다면 외부 검색으로 인터뷰를 대체하지 않는다.

## 내부 분석

사용자에게 질문하기 전에 내부적으로 다음 순서로 분석한다.

### 1. 설득 논리 분해

대본을 문장 수가 아니라 의미 변화 기준으로 나누고 각 구간을 다음 중 하나로 분류한다.

- `hook`: 즉시 주목시킬 문제나 결과
- `problem`: 불편, 결핍, 위험 또는 실패 상태
- `cause`: 문제가 생기는 이유
- `objection`: 기존 해결책의 한계나 사용 장벽
- `solution`: 제품 또는 해결책의 등장
- `mechanism`: 제품이 작동하거나 변화시키는 과정
- `ingredient_or_build`: 원료, 소재, 구조 또는 제조 특성
- `use`: 사용 방법과 제품 상호작용
- `result`: 사용 뒤 보이는 상태
- `proof`: 시각적으로 제시할 수 있는 근거
- `value`: 구성, 편의 또는 선택 이유
- `cta`: 다음 행동

### 2. 시각 표현 단위 도출

각 대본 구간에 대해 다음을 정리한다.

| 필드 | 의미 |
|---|---|
| `viewer_takeaway` | 시청자가 그 장면에서 하나만 이해해야 한다면 무엇인지 |
| `visible_subject` | 화면에 실제로 보여야 하는 사람, 제품, 재료 또는 공간 |
| `initial_state` | 변화 전 상태 |
| `trigger_or_action` | 변화나 이해를 일으키는 행동 |
| `transformation` | 퍼짐, 흡수, 조립, 감소, 이동, 비교 등 변화 과정 |
| `final_state` | 장면이 끝날 때 보여야 하는 상태 |
| `setting` | 의미상 필요한 환경 |
| `composition_dependency` | 답에 따라 구도나 주 피사체가 달라지는 정보 |
| `known_source` | 대본 또는 사용자가 이미 제공한 근거 |
| `missing_visual_fact` | 아직 알 수 없는 핵심 시각 정보 |

### 3. 질문 필요성 판정

다음 질문에 `예`일 때만 사용자에게 묻는다.

> 가능한 답 A와 답 B가 영상의 피사체, 동작, 재료, 공간, 상태 변화, 카메라 구도 또는 최종 화면을 서로 다르게 만드는가?

다음 정보는 보통 질문 가치가 높다.

- 제품과 포장의 실제 형태, 크기, 색, 재질, 구성
- 내용물의 실제 색, 입자, 점도, 표면, 투명도 또는 소리
- 물, 피부, 음식, 기계 또는 신체와 만났을 때 실제로 일어나는 변화
- 일반 제품과 구분되는 핵심 물성 또는 사용 행동
- 대본에서 중요하게 다루는 원료의 실제 모습과 대표성
- 산지, 사찰, 연구실, 공장, 주방 등 출처나 공간이 제품 의미의 일부일 때 그 구체적 맥락
- 사용자의 손동작, 도구, 순서 또는 사용 환경
- 결과를 어느 정도 사실적이거나 과장되게 보여줄지에 대한 경계
- 동일하게 유지해야 할 공식 제품 이미지 또는 캐릭터 앵커

다음 정보는 특정 장면이 직접 의존하지 않는 한 현재 인터뷰에서 묻지 않는다.

- 전체 회사 소개와 브랜드 연혁
- 가격, 할인, 구매 링크와 광고 채널
- 예산, 납기, 영상 모델과 출력 설정
- 성우, 배경음악, 전체 자막 형식
- 법적 문구, 심의 자료와 게시 승인
- 완판, 후기, 재구매, 통계의 증빙 전체
- 대본에 이미 명확히 적힌 수치와 문장

이 정보가 대본 속 `proof`, `value` 또는 `cta` 장면의 실제 화면을 결정한다면 인터뷰 본문과 분리해 `후반 표현 자료`로 표시한다. 현재 핵심 질문 수를 부풀리지 않는다.

## 질문 우선순위

질문 후보를 다음 순서로 정렬한다.

1. 여러 장면의 물성과 메커니즘을 동시에 결정하는 정보
2. 제품이 다른 것으로 보이게 만들 수 있는 공식 외형 정보
3. 대본의 핵심 차별점과 전후 상태를 결정하는 정보
4. 공간, 인물 또는 사용 행동을 크게 바꾸는 정보
5. 한 장면의 작은 소품만 바꾸는 정보

일반 호출에서는 한 턴에 최대 3개의 질문만 한다. `finalized_script_detail` 프로필에서는 한 턴에 최대 6개의 묶음 질문을 허용한다. 서로 같은 결정을 요구하는 세부 항목은 하나의 이해하기 쉬운 질문으로 묶는다. 질문마다 `이 답이 어떤 장면을 바꾸는지`를 한 문장으로 설명한다. 이미 답한 내용, 합리적으로 정할 수 있는 저위험 기본값, 영상 표현과 무관한 정보는 다시 묻지 않는다. 단, 사용자가 임의 설정을 금지한 고영향 변수는 저위험 기본값으로 간주하지 않는다.

## 인터뷰 문체

- 사용자의 제품 이해 수준에 맞는 일상어를 사용한다.
- 거대한 체크리스트나 20개 이상의 입력 양식을 먼저 제시하지 않는다.
- `제품 정보 전부`, `증빙 전부`, `마케팅 자료 전부`처럼 범위가 불명확한 요청을 하지 않는다.
- 사용자가 무엇을 보내야 하는지 사진, 설명, 선택지 중 가장 쉬운 형태로 제안한다.
- 질문이 필요하지 않으면 억지로 만들지 말고 현재 정보로 충분하다고 말한다.

권장 형식:

```markdown
현재 영상 표현을 확정하는 데 필요한 정보는 2가지입니다.

1. [핵심 질문]
   - 보내주실 것: [사진 또는 짧은 설명]
   - 이 답으로 달라지는 장면: [물성, 동작, 공간 또는 결과]

2. [핵심 질문]
   - 보내주실 것: [사진 또는 짧은 설명]
   - 이 답으로 달라지는 장면: [물성, 동작, 공간 또는 결과]
```

## 답변 처리

- 사용자가 `알아서`, `기본값`, `자연스럽게`라고 답하면 가장 대본 논리에 맞는 보수적 가정을 선택하고 공개한다.
- 공식 제품 외형을 모르면 생성 모델이 읽을 수 있는 라벨이나 로고를 발명하지 않는다. 공식 제품 컷아웃을 나중에 합성할 대상으로 분리한다.
- 실제 물성이나 메커니즘을 모르면 사실처럼 구체화하지 않는다. 추상적이고 보수적인 시각 은유를 선택하고 `가정`으로 표시한다.
- 답변이 모호해도 장면이 크게 달라지지 않으면 추가 질문하지 않는다.
- 답변이 서로 충돌하면 충돌한 한 가지 결정만 다시 확인한다.

## 인터뷰 종료 조건과 핸드오프

모든 중요한 대본 구간에 실제 정보 또는 공개된 가정이 하나씩 연결되면 인터뷰를 종료한다. 다음 형식으로 후속 영상 기획 스킬에 넘길 수 있는 요약을 만든다.

```markdown
## 대본 표현 정보 요약

- 제품 앵커:
- 핵심 시각 차별점:
- 실제 물성 및 변화:
- 대표 원료 또는 구조:
- 사용 행동:
- 핵심 공간:
- 인물 또는 캐릭터:
- 보여줄 전 상태:
- 보여줄 후 상태:
- 표현 강도 및 금지선:

## 장면 적용
| 대본 구간 | 시각적으로 확정된 내용 | 정보 출처 | 남은 가정 |
|---|---|---|---|

## 후반 표현 자료
- 정확한 문구나 증빙이 있어야만 추가할 요소

`ready_for_visual_planning: yes|no`
```

`ready_for_visual_planning: yes`는 시각 기획을 시작할 정보가 충분하다는 뜻일 뿐, 효능·수치·후기·혜택이 검증되었다는 뜻이 아니다.

## 판단 예시

### 분말형 식품 대본

물에 퍼지고 부푸는 과정이 핵심이면 제품 사진, 분말의 실제 물성, 물에서의 변화, 대표 원료와 출처 공간만 묻는다. 판매 증빙, 예산, 성우와 구매 링크는 묻지 않는다.

### 화장품 대본

제형, 바르는 양과 도구, 피부에 닿을 때의 변화, 표현 가능한 전후 상태만 묻는다. 가격과 전체 브랜드 연혁은 묻지 않는다.

### 생활가전 대본

제품 크기와 형태, 사용자의 조작, 작동 중 실제 움직임, 설치 환경과 결과 상태만 묻는다. 배송 혜택과 광고 매체는 묻지 않는다.
