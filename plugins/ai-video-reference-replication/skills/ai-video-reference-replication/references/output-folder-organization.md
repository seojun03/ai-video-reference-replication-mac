# 날짜별 생성 결과물 정리

사용자에게 보이는 결과물은 **날짜 → 생성 클린본** 구조로 저장한다. 같은 제품에서 같은 날 만든 첫 영상, 추가 장면, 보조 컷은 모두 같은 `생성 클린본` 폴더에 이어서 모은다. 작업명·모델명·버전·장면 묶음별 클린본 폴더를 따로 노출하지 않는다.

```text
생성 결과물/
├── 2026-08-31/
│   ├── 생성 클린본/
│   │   ├── 001_세안 후 따가움.mp4
│   │   ├── 002_붉어진 볼.mp4
│   │   └── ...같은 날 추가한 영상도 여기...
│   ├── 기획 자료/        필요한 자료가 있을 때만 생성
│   ├── 음성/
│   ├── 편집 자료/
│   ├── 작업 기록/        생성 원본, 검수, 이전 버전, 자동화 기록
│   └── 폴더 안내.md
└── 2026-09-01/
    └── 생성 클린본/
```

- 날짜는 한국시간의 실제 생성 완료일 `YYYY-MM-DD`다. 자정을 넘겨 생성했다면 작업 시작일과 구분한다. 이전 결과물은 생성 기록으로 날짜를 확인하고, 이동 후 수정일로 날짜를 다시 정하지 않는다.
- 날짜 안에서 번호를 계속 증가시킨다. 파일 이름은 짧은 한글 장면 설명을 쓴다. 다른 내용의 같은 번호를 덮어쓰지 않는다.
- `작업 기록` 아래에는 실행별 독립 폴더와 기존 기술 파일명을 보존할 수 있다. 기획·음성·편집 등 사용자 접근 폴더는 한글로 표시한다. 새 작업부터 긴 영문 실행 폴더를 결과물 최상단에 만들지 않는다.
- 추가 작업/보조 컷의 승인·비용·QC·재시도 기록은 계속 실행별로 구분한다. 물리적 클린본 폴더를 합치는 것이 계획이나 승인 범위를 합치는 것은 아니다.
- 검수 실패·보류·대체된 버전은 `작업 기록/검토 필요 영상` 또는 해당 실행 기록에 보존하고 사용 클린본에 섞지 않는다. 이전 작업의 QC 상태를 폴더 정리 때문에 바꾸지 않는다.

## 새 작업 시작

결과물이나 계획 파일을 만들기 전에 아래 명령으로 날짜 폴더와 내부 기록 위치를 받는다. 같은 날 여러 번 실행해도 `final_clean_clips_dir`은 동일하며 `run_dir`만 `작업 기록` 안에서 구분된다.

```sh
python3 scripts/organize_result_folders.py \
  --output-root '/정확한 제품/생성 결과물' \
  --date 2026-08-31 --init-run --run-label '레퍼런스 작업'
```

최종 사용 영상 외의 중간 이미지·생성 원본·검사 자료는 반환된 `run_dir`에 보관한다. 위의 날짜는 예시이며 매 작업의 실제 날짜를 쓴다.

## 검수 후 같은 날짜 폴더에 모으기

검수 통과 파일만 명시한다. `--clips-json`은 아래 목록 형식이다. 중간 번호가 빠졌더라도 실패 컷을 끼워 넣지 않는다.

```json
[
  {"source": "/절대경로/이번제품/생성 결과물/작업경로/cut-01.mp4", "name": "피부장벽 붕괴"},
  {"source": "/절대경로/이번제품/생성 결과물/작업경로/cut-04.mp4", "name": "투명막 형성"}
]
```

```sh
python3 scripts/organize_result_folders.py \
  --output-root '/정확한 제품/생성 결과물' \
  --run-dir '/정확한 제품/생성 결과물/2026-08-31/작업 기록/추가 장면 001' \
  --date 2026-08-31 --clips-json '/작업/통과 클린본 목록.json' --expected-count 2
```

- `--dry-run`으로 이동 예정 경로를 먼저 확인할 수 있다.
- 연속된 최종 폴더 전체가 사용본이면 기존 `--final-dir ... --expected-count N --batch-name '한글 설명'`도 지원한다. `expected_count`는 **이번 입력 묶음**의 수이고 `daily_total_count`는 날짜 폴더 전체 수다. 날짜 폴더의 전체 수를 이번 작업의 계획 컷 수와 비교하지 않는다.
- 반환된 `files`의 파일별 경로를 새 매니페스트에 기록한다. 날짜 폴더가 `cut-01.mp4`부터 다시 시작한다고 추정하지 않는다.
- 이전 영문 실행 폴더를 정리할 때만 `--archive-run --run-label '한글 작업명'`을 사용한다. 기존 작업 전체 재정리는 사용자 요청 범위에서만 한다.
- `--raw-dir`, `--capcut-dir`, `--history-link`를 쓰면 각각 `작업 기록` 또는 `편집 자료` 아래에 연결된다. CapCut 프로젝트 자체를 옮기거나 편집하지 않는다.

## 보존과 검증

같은 파일시스템에서 영상 데이터를 복사하지 않는 이동과 호환 링크를 쓴다. 새 영상 생성·재인코딩·중복 렌더는 하지 않는다. 이전 자동화·CapCut 참조 경로는 그대로 열려야 한다. 호환 링크는 macOS Finder에서 **링크 자신만 숨김** 처리해 날짜 폴더 외의 옛 이름이 다시 보이지 않게 한다. 링크 대상 폴더까지 숨기지 않는다.

현재 날짜 목록에 같은 SHA-256이 있으면 새 항목을 만들지 않는다. 이미 존재하던 별도 원본 복사본을 임의 삭제하지 않는다. 목록에 없는 대상 파일, 내용이 바뀐 기존 파일, 다른 제품의 경로, 다른 파일시스템은 덮어쓰기/강제 병합 없이 중단한다. 실패 후 기존 파일을 삭제하거나 기존 기록을 조작해 재실행하지 않는다.

`작업 기록/클린본 목록.json`에 날짜, 한글 파일명, 현재 경로, SHA-256, 이전 경로와 일일 총수를 누적 기록한다. 이동 전후 해시, 실제 파일 수, 옛 경로/연결, 기존 CapCut 참조를 검사한다. 서명되거나 해시로 고정된 과거 작업 기록은 일괄 경로 치환하지 않고 호환 링크로 보존한다.

완료 응답에는 **날짜 폴더**, **생성 클린본 폴더**, 현재 날짜의 영상 개수와 경로 검증 결과를 짧게 제공한다. 기존 `01_최종_영상클린본_N컷`, 영문 장면별 폴더, raw/QC 폴더를 사용자 최상위 진입점으로 안내하지 않는다.
