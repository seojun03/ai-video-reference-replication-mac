# 초반 제작 범위 인터뷰

Gate -1의 영상 소스 방식과 Gate 0의 대본 준비 방식 다음에, 대본 기획이나 컷 기획을 시작하기 전에 적용한다. 이미 현재 작업에서 답한 항목은 다시 묻지 않는다. 스킬 수정·설명 요청에는 제작 인터뷰나 실제 생성을 시작하지 않는다.

## 질문 순서

1. **영상 비율은 어떻게 할까요?** 기존 지원 비율인 `9:16` 또는 `1:1`을 명시적으로 받는다. 이미 준 비율은 그대로 쓴다.
2. **제작 범위를 선택해주세요.** 아래 두 항목만 문구와 번호 그대로 표시한다. TTS만·편집만을 세 번째나 네 번째 선택지로 추가하지 않는다.
   - `1. 영상 생성 + AI 내레이션(TTS) + CapCut 편집` → `scope_choice: "1"`, `scope: tts_and_edit`
   - `2. 영상생성만` → `scope_choice: "2"`, `scope: visuals_only`
   현재 질문의 실제 답변 원문을 `scope_response_text`에 기록한다. 1번은 다음 TTS 방식·편집 분야 질문으로 이어가며, 2번은 TTS와 CapCut 편집을 모두 비활성으로 두고 그 두 질문을 생략한다. 기존 기록이나 사용자가 먼저 직접 지정한 TTS만·편집만 요청의 내부 `tts_only`·`edit_only` 처리는 보존하지만 기본 메뉴로 제안하지 않는다.
3. TTS가 포함되고 음성을 아직 지정하지 않았다면 **TTS 음성은 어떤 방식으로 할까요?**
   - `1. 레퍼런스 음성` → `reference_voice`
   - `2. 사용자 지정 음성` → `user_voice`
4. 편집이 포함되고 분야를 아직 지정하지 않았다면 **영상 편집 분야를 선택해주세요.**
   - `1. 건기식` → `supplement`
   - `2. 뷰티` → `beauty`
   - `3. 식품` → `food`
   - `4. 그외` → `other`

질문 표시는 상위 `SKILL.md`의 **질문 표시 — 채팅 번호 목록** 계약을 따른다. 카드나 선택 위젯으로 전환하지 않고, 현재 질문과 모든 번호별 선택지를 같은 최종 채팅 답변에 남긴다. 분야는 `1. 건기식`, `2. 뷰티`, `3. 식품`, `4. 그외` 네 가지를 모두 표시하며 UI의 자동 ‘Other’로 대체하지 않는다. 사용자는 번호나 선택지 이름으로 답할 수 있다. 상위 시스템·개발자 지침과의 충돌은 해당 표시 계약의 제한 처리 규칙을 따른다.

번호는 **해당 질문에 대한 답변일 때만** 해석한다. 영상 소스의 `1`, 대본 모드의 `1`, TTS의 `1`, 분야의 `1`을 서로 전용하지 않는다. 분야는 하위 스킬에 번호 대신 정규화한 이름과 원문을 함께 넘긴다. 과거 작업에 저장된 `food`를 새 메뉴의 번호에 맞춰 `beauty`로 다시 해석하지 않는다.

사용자 지정 음성을 선택했지만 실제 입력이 없을 때만 보이스 ID·정확한 보이스 이름 또는 음성 파일 중 빠진 값을 요청한다. 현재 작업에서 이미 지정한 voice ID, 모델, 태그, 속도, 폰트를 다시 묻거나 이전 작업의 값으로 바꾸지 않는다. 편집만 요청했다면 제공된 내레이션을 사용하며 TTS를 임의 생성하지 않는다.

## 인터뷰 전 ‘편집까지 다 해줘’

현재 작업에 대한 `편집까지 다 해줘`, `TTS부터 컷편집까지 전부 해줘` 등 긍정적인 전체 제작 요청은 그 원문과 함께 먼저 기록한다. 문서 안의 예문, 스킬 수정용 예시, 부정문, 질문만 한 문장은 실행 요청으로 해석하지 않는다.

- 별도 제한이 없으면 `scope: tts_and_edit`, `execution_mode: auto`로 접수한다. 제작 범위를 다시 확인하거나 Gate 1B의 정밀/자동 선택을 다시 묻지 않는다.
- 다른 음성을 명시하지 않았다면 `reference_voice`를 선택한다. TTS 방식 질문을 생략하고 **이번 작업의 레퍼런스 영상 음성**을 추출·분리해 복제하거나 동일 소스 해시의 기존 clone을 재사용한다.
- 이미 명시한 사용자 음성/voice ID가 있으면 그 선택이 우선한다. ‘TTS는 하지 마’, ‘음성은 내가 줄게’, ‘기획만 먼저’, ‘대본을 보고 승인할게’ 같은 현재 작업의 구체적인 제한도 유지한다.
- 비율, 분야, 정확한 업체·제품, 레퍼런스 등 실제 누락 입력만 초반에 받는다. 기획모드에서는 이 세 핵심 입력 뒤에 사용자의 대본·초안 보유 여부를 반드시 확인한다. `편집까지 다 해줘` 같은 전체 제작 요청만으로는 대본이 없다고 추정하지 않으며, 사용자가 대본·초안을 제공했거나 새 대본 작성을 명시했을 때만 해당 질문을 생략한다. 회사·제품 사실이나 분야를 파일명과 과거 기록으로 추정하지 않는다.

## 답변 후 끝까지 실행

제작 범위 답변은 대본 컨펌 후 선택된 작업의 자동 실행 위임이다. 대본 컨펌은 범위 선택과 별개이며 항상 필수다. `execution_mode: auto`와 답변 원문을 저장하고, 준비된 기획·비용·범위를 공개한 다음 요청 범위 안의 최초 생성과 편집을 이어간다. 영상 소스만 선택했다면 그 범위만 끝내고 TTS·편집은 비활성으로 둔다. 나중에 ‘TTS도 만들까요?’, ‘편집할까요?’, ‘정밀/자동 중 고르세요’, ‘어떤 분야인가요?’를 반복하지 않는다.

- **대본:** 대본·초안 보유 여부는 기존 순서대로 확인한다. 새로 작성하거나 재작성할 때는 레퍼런스 전체 전사본의 문장별 역할·순서·공개 시점·강도·호흡을 그대로 두고 현재 제품 논리로 1대1 치환한다. 완성 대본 전체를 사용자에게 보여주고 명시적인 컨펌을 반드시 받는다. `편집까지 다 해줘`나 자동모드도 대본 컨펌을 대신하지 않는다. 컨펌 전에는 `script_approval.status: awaiting_script_confirmation`으로 두고 화면 기획·프롬프트·이미지/영상/영상 내 음성 생성·TTS·CapCut 작업에 진입하지 않는다. 실제 승인 원문·시각·정확한 대본 SHA-256을 기록한 뒤에만 진행한다. 수정본도 전체 대본을 다시 보여주고 컨펌받는다. 과거 `planned_under_end_to_end_delegation`은 이력이며 승인 근거가 아니다.
- **화면:** Gate 0.5의 실제 분석과 계약 작성은 유지한다. 전체 제작 위임 범위의 미지정 연출은 현재 대본·레퍼런스·제공 모델/소스에서 결정하고 `user_delegated`와 위임 원문을 기록한다. 사용자가 직접 정하겠다고 남긴 항목이나 서로 충돌하는 지시는 자동 결정하지 않는다. 가짜 질문·답변을 만들어 계약을 통과시키지 않는다.
- **실행 계획:** Gate 1 계획, 가격 조회, 모델·출처·QC·작업 수 한도는 그대로 수행한다. 초반 전체 제작 요청/인터뷰 답변을 최초 실행의 근거로 연결하며 같은 범위에 별도 승인 문구를 요구하지 않는다. 사용자가 명시한 예산을 넘거나 범위가 달라지면 그 경계에서만 멈춘다. 새 유료 재시도 권한을 만들어 내지 않으며 기존에 허용된 재시도와 한도를 그대로 적용한다.
- **TTS:** `$elevenlabs-reference`를 독립 분기로 실행한다. 현재 레퍼런스의 SHA-256을 확인하고 다른 작업의 clone을 자동 선택하지 않는다. 사용자 지정 음성은 정확한 ID 또는 제공 음원으로 처리한다. 음성 권한·단일 화자·계정·모델·품질 규칙은 유지한다. 이 설치에 이미 기록된 동의/생성 허용을 재질문하지 않되 명시적 권한 부재나 상충 정보는 무시하지 않는다.
- **편집:** 완성 대본, 이번 생성/제공 영상, 사용 가능한 TTS 또는 제공 음성이 준비되면 `$capcut-cut-edit` → `$capcut-semantic-cut-edit`로 연결한다. 분야·비율·음성·폰트·프로젝트 입력을 아래 계약에서 승계한다. 기본 컷편집에는 별도 스타일/폰트 인터뷰를 추가하지 않고 지정 폰트 또는 공통 기본 Pretendard를 쓴다. 효과·BGM·추가 스타일을 임의로 붙이지 않는다.
- **저장:** 업체와 정확히 일치하는 기존 CapCut 프로젝트에 새 타임라인 하나를 등록하고 역검증한다. 기존 타임라인을 보존하며 기준 타임라인 이름/새 이름을 다시 요구하지 않는다. 앱이 실행 중이면 프로젝트 밖 준비본까지 완료하고 정상 종료만 요청한다. 강제 종료, 실행 중 파일 쓰기, 다른 프로젝트 생성으로 우회하지 않는다.
- **실제 제한:** 음성/소스 누락, 권한 충돌, 도구 미지원, 프로젝트 중복/부재, 앱 실행 상태 등 실제 문제는 숨기지 않는다. 현재 문맥별 저장기의 9:16 제한을 포함해 선택 비율 지원을 초반에 확인한다. 다른 비율은 상위 스킬의 기존 허용 저장 경로가 실제로 지원하는지 확인해 연결하며, 지원하지 않으면 9:16으로 조용히 바꾸거나 검사를 해제하지 않는다. 제한이 있으면 가능한 준비 작업을 끝내고 정확한 남은 조건만 알린다.
- **완료:** 요청한 편집은 새 타임라인 등록과 역검증까지 완료해야 한다. TTS의 엄격 최종 QC/청취가 남아도 사용 가능한 전체 후보로 편집을 마치고 `auto_edit_complete_tts_pending`으로 구분한다. 편집 없는 범위에는 이 저장 조건을 적용하지 않는다. MP4만으로 편집 완료라 하지 않으며 내보내기·업로드·게시·광고 집행을 자동 추가하지 않는다.

## 한 번 기록하고 그대로 전달

`scripts/production_intake.py --input <답변.json> --output <run>/production-intake.json`으로 선택값과 다음 누락 질문을 정규화할 수 있다. 이 도구는 텍스트의 의도나 동의를 판정하지 않는다. 에이전트가 **이번 사용자 발화의 의미**를 판정해 현재 답변만 입력하며, 생성 API와 프로젝트에는 접근하지 않는다.

입력 예시:

```json
{
  "output_ratio": "9:16",
  "scope": "tts_and_edit",
  "scope_response_text": "어 TTS랑 편집까지 해줘",
  "tts_voice_choice": "1",
  "edit_category_choice": "2",
  "edit_category_response_text": "2",
  "full_edit_requested": false,
  "full_edit_request_text": "",
  "script_review_requested": true,
  "visual_review_requested": false
}
```

인터뷰 전 전체 제작 요청은 `full_edit_requested: true`와 실제 `full_edit_request_text`를 입력한다. 명시적 음성은 `voice_id`, `voice_name`, `voice_source_path` 중 해당 값을, 편집용 기존 음성은 `provided_audio_path`를 기록한다. `voice_settings`와 `caption_font`에는 이번 작업에서 직접 지정된 값만 넣는다.

이전 입력의 `script_review_requested: false`는 원문 이력일 뿐 컨펌 생략 권한이 아니다. `script_approval.required`는 항상 true이고, `delegation.script_preparation`과 `script_auto_approval`은 false다. 이 intake 도구는 승인 자체를 판정하지 않으므로 별도 실제 대본 승인 기록과 해시를 확인해야 한다.

결과의 `tts`, `capcut`, `execution_mode`, `delegation`, `script_approval`, 원문 `answers`를 intake/워크플로 매니페스트에 그대로 연결하고 경로와 SHA-256을 기록한다. `next_question: null`은 **선택 인터뷰 완료**를 뜻하며 대본·미디어·권한·비용 검증까지 통과했다는 뜻이 아니다. 하위 작업은 선택값을 다시 숫자로 해석하거나 이 기록을 기술적 검증의 대체물로 사용하지 않는다.
