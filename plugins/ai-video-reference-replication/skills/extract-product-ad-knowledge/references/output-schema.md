# 제품 광고 지식 문서 출력 규격

## 목차

1. 작성 원칙
2. 필수 섹션
3. 출처 표기
4. AI 마스터 프롬프트
5. 선택 JSON 부록

## 1. 작성 원칙

- 문서는 단독으로 전달해도 이해되어야 한다.
- 사실과 광고 기획을 한 문장 안에서 섞지 않는다.
- 수치에는 출처 위치와 확인일을 붙인다.
- 모르는 정보를 추정하지 말고 `확인 필요`에 넣는다.
- 제품을 칭찬하는 형용사보다 그 근거가 되는 원물·공정·포장 방식을 우선한다.
- 동적 정보에는 `기준일 현재`를 명시한다.

## 2. 필수 섹션

아래 제목을 기본으로 사용한다. 제품에 해당하지 않는 내용은 `페이지에서 확인되지 않음`으로 남긴다.

```markdown
# [브랜드] [제품명] 광고용 AI 제품 지식 문서

## 1. 소스 기록
## 2. 제품 핵심 정의
## 3. 제품 정체성과 기본 사양
## 4. 사실 원장
### 확인된 사실
### 페이지 주장
### 동적 정보
### 광고 해석
### 확인 필요
## 5. 원재료·원산지·제조 공정
## 6. 맛·향·식감과 비주얼
## 7. 소비자 문제와 해결 논리
## 8. 타깃과 사용 상황
## 9. 가격·옵션·배송·프로모션
## 10. 사회적 증거와 인증
## 11. 광고 메시지와 콘텐츠 아이디어
## 12. 반론 대응
## 13. 광고 주장 안전성
## 14. 추가 확보가 필요한 정보
## 15. AI 마스터 프롬프트
## 16. 출처 추적표
```

### 제품 핵심 정의

한 문장으로 다음 구조를 사용한다.

`[누구를 위한] [무엇]이며, [원물·공정 근거]로 [감각적·실용적 이점]을 제공한다고 소개되는 제품`

### 사실 원장

`확인된 사실`, `페이지 주장`, `동적 정보`, `광고 해석`, `확인 필요`를 반드시 별도 소제목으로 둔다.

### 가격 표

옵션이 있으면 다음 열을 사용한다.

| 구성 | 총액 | 단가 | 배송 | 사은품 | 기준일 |
|---|---:|---:|---|---|---|

기본가에 옵션 추가금이 붙는 페이지는 실제 총액을 계산하고, 선택 목록의 표시 단가와 일치하는지 확인한다.

### 광고 주장 안전성

최소한 다음 세 묶음으로 정리한다.

- 그대로 사용 가능한 표현
- 증빙 후 사용할 표현
- 사용 금지 또는 완화가 필요한 표현

## 3. 출처 표기

문서 마지막에 주요 주장별 출처 추적표를 둔다.

| 주장 | 분류 | 출처 위치 | 확인일 | 증빙 필요 |
|---|---|---|---|---|
| 1봉 100g | 확인된 사실 | 패키지 전면 이미지 | YYYY-MM-DD | 아니오 |
| 누적 150만 개 | 페이지 주장 | 상세 이미지 1 | YYYY-MM-DD | 예 |
| 남은 수량 103개 | 동적 정보 | 구매 영역 | YYYY-MM-DD | 집행 시 재확인 |

출처 위치 예시:

- 구매 영역
- 본품 옵션 셀렉트
- 상품 메타 description
- JSON-LD Product.offers
- 상세 이미지 05
- 패키지 전면
- 배송 안내
- 리뷰 게시판

## 4. AI 마스터 프롬프트

다른 AI에 그대로 넣을 수 있도록 코드 블록으로 작성한다.

```text
너는 [브랜드] [제품]의 광고 기획자다.
아래 제품 지식만 사실로 사용하고, 없는 원재료·영양·효능·수치를 만들지 마라.

[제품 정의]
- ...

[확인된 사실]
- ...

[페이지 주장: 증빙 후 광고 사용]
- ...

[동적 정보: 기준일과 재확인 필요]
- ...

[타깃]
- ...

[메시지 우선순위]
1. ...

[표현 원칙]
- 절대 표현을 공정 근거로 바꿔라.
- 모르는 정보는 추정하지 마라.
- 인증은 규격과 범위를 정확히 써라.
- 가격·재고·배송일은 게시 전에 다시 확인하라.

[브랜드 비주얼]
- ...

요청받은 매체와 길이에 맞게 작성하되, 첫 부분에서 소비자 불편 또는 핵심 차별점을 제시하고 공정 근거, 체감 이점, CTA 순서로 연결하라.
```

## 5. 선택 JSON 부록

사용자가 기계 판독용 결과를 요청하면 다음 최상위 키를 사용한다.

```json
{
  "source": {
    "url": "",
    "checked_at": "",
    "source_types": []
  },
  "product_identity": {},
  "verified_facts": [],
  "page_claims_requiring_evidence": [],
  "dynamic_commerce_snapshot": {},
  "ingredients_and_manufacturing": {},
  "sensory_and_visual_language": {},
  "audiences_and_occasions": [],
  "pain_solution_map": [],
  "ad_message_pillars": [],
  "claim_safety": {
    "safe": [],
    "verify_first": [],
    "avoid_or_soften": []
  },
  "missing_information": [],
  "provenance": []
}
```

JSON 값에도 추정 사실을 넣지 않는다. 정보가 없으면 빈 값이나 `null`을 사용하고 `missing_information`에 이유를 기록한다.
