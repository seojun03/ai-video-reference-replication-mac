# Extract Product Ad Knowledge

상세페이지를 광고 제작용 AI 문맥·지식베이스로 변환한다. 단순 요약이 아니라 출처, 주장 강도, 동적 정보, 누락 정보를 분리해 재사용 가능한 제품 기준 문서를 만든다.

## 핵심 원칙

1. 페이지에 없는 사실을 만들지 않는다.
2. `확인된 사실`, `페이지 주장`, `동적 정보`, `광고 해석`, `확인 필요`를 구분한다.
3. 이미지형 상세페이지의 문구를 빠뜨리지 않는다.
4. 강한 광고 수치는 실증 필요 여부를 표시한다.
5. `AI 학습`을 모델 가중치 학습으로 오해하지 말고 프롬프트, RAG, 지식베이스에 넣기 좋은 문서로 제공한다.
6. 최종 문서에는 다른 AI가 그대로 사용할 수 있는 마스터 프롬프트를 포함한다.

## 워크플로

### 1. 입력과 범위 확정

- 사용자가 `이 페이지`, `여기`, `현재 탭`이라고 하면 선택된 Chrome 탭을 대상으로 한다.
- 활성 탭 콘텐츠에 관한 요청이면 먼저 `getTabContext`로 본문, 제목, URL을 읽는다.
- URL, HTML, PDF, 이미지 묶음이 주어지면 해당 자료를 우선 소스로 삼는다.
- 확인 날짜와 페이지 URL을 기록한다.
- 여러 상품이 섞여 있으면 본품과 추가구성상품을 분리한다.
- 가격·재고·배송일·리뷰 수는 스냅샷 정보로 취급한다.

### 2. 상세페이지 전체 소스 수집

텍스트 한 번 읽고 끝내지 말고 다음 항목을 확인한다.

- 상품명, 브랜드, 카테고리, 판매자
- 판매가, 정상가, 할인율, 쿠폰, 사은품, 배송 조건
- 모든 본품 옵션과 옵션별 총액·단가
- 본문 텍스트, 탭, 구매안내, Q&A, 리뷰
- `meta`, Open Graph, JSON-LD의 Product·Offer·AggregateRating
- 대표 이미지와 추가 이미지
- 상세 설명 이미지 안의 문구와 시각 요소
- 인증서, 시험성적서, 수치, 날짜, 사업자 정보

이미지형 페이지에서는 특히 다음을 확인한다.

- `src`뿐 아니라 `data-src`, `ec-data-src`, `data-original` 등 지연 로딩 속성
- 자연 크기가 1×1인 플레이스홀더 뒤의 원본 이미지 주소
- 데스크톱·모바일용 중복 이미지
- GIF의 첫 프레임과 반복되는 주장
- 이미지에만 보이는 내용량, 원산지, 함량, 제조 공정, 인증

현재 Chrome 탭을 더 깊게 조사해야 하면 `chrome:control-chrome` 스킬을 먼저 읽고 그 지침대로 작업한다. 페이지를 읽는 작업만 수행하고 구매, 로그인, 폼 제출, 장바구니 추가 같은 외부 변경은 하지 않는다.

### 3. 사실 원장 작성

수집한 내용을 아래 다섯 분류로 먼저 정리한 뒤 광고 문서를 작성한다.

| 분류 | 의미 | 예시 |
|---|---|---|
| 확인된 사실 | 페이지나 포장 전면에 명확히 표시 | 100g, 호두 78%, 판매가 |
| 페이지 주장 | 브랜드가 말하지만 외부 증빙은 미확인 | 누적 150만 개, 840시간 연구 |
| 동적 정보 | 시점에 따라 바뀜 | 재고 103개, 오늘출발, 리뷰 192개 |
| 광고 해석 | 사실에서 도출한 메시지 전략 | 쩐내 불편을 공정 근거로 해결 |
| 확인 필요 | 페이지에 없거나 모호함 | 전체 원재료, 소비기한, 알레르기 |

서로 충돌하는 정보가 있으면 숨기지 말고 각각의 위치와 차이를 기록한다. 예를 들어 화면 주문 수와 JSON-LD 리뷰 수가 다르면 별도 수치로 보존한다.

### 4. 제품 지식 구조화

다음 체크리스트를 빠짐없이 검토한다.

- 제품 정체성: 브랜드, 상품명, 카테고리, 용량, 형태
- 원재료·원산지·함량: 확인되는 범위만
- 제조 방식과 품질관리: 공정을 순서대로
- 감각 정보: 맛, 향, 식감, 색, 크기, 패키지
- 소비자 문제와 해결 논리
- 타깃과 구매 상황
- 가격, 옵션, 배송, 사은품, 회원 혜택
- 사회적 증거: 매출, 판매량, 평점, 리뷰, 인증
- 브랜드 보이스와 비주얼 언어
- 광고 후킹 소재, 콘텐츠 장면, 반론 대응
- 광고 표현상 위험과 필요한 증빙
- 페이지에 없는 필수 정보

리뷰는 브랜드 사실과 섞지 않는다. 실제 리뷰가 구체적일 때만 `소비자 의견`으로 요약하고, 자동 생성형·짧은 만족 문구는 강한 제품 근거로 사용하지 않는다.

### 5. 주장 안전성 검사

다음 표현을 발견하면 자동으로 검증 대상으로 표시한다.

- `100%`, `ZERO`, `없다`, `절대`, `최고`, `유일`, `1위`
- 건강, 다이어트, 혈당, 저당, 저칼로리, 질병·의학 효과
- 아이·임산부·환자에게 좋다는 표현
- 누적 판매, 매출, 재구매율, 연구 시간, 순위
- 특허, HACCP, ISO, 유기농, 비건 등 인증
- 정상가, 할인율, 한정수량, 무료, 사은품, 오늘출발

표현의 대상을 정확히 해석한다. 예를 들어 `100% 수제`를 `원재료 100%`로 바꾸지 않는다. `튀기지 않음`을 `무오일`로 확장하지 않는다. ISO 인증은 인증서에 적힌 정확한 규격과 범위만 쓴다.

강한 표현은 가능한 경우 다음처럼 공정 중심으로 완화한다.

- `쩐내 ZERO` → `쩐내를 줄이기 위한 보관·제조·포장 관리`
- `기름 0` → `기름에 튀기지 않고 오븐에 구움`
- `설탕보다 건강` → `비정제원당 사용`
- `식품안전 ISO` → `ISO 9001·14001·45001 인증`처럼 정확한 명칭

### 6. 결과물 생성

최종 문서를 작성하기 전에 [references/output-schema.md](references/output-schema.md)를 전부 읽고 그 구조를 따른다.

- 기본 결과는 Markdown 제품 지식 문서로 만든다.
- 긴 결과가 재사용에 유리하면 환경이 지정한 사용자용 출력 폴더에 저장한다.
- 사용자에게는 핵심 포지션과 파일 링크를 함께 전달한다.
- 사용자가 `JSON`, `RAG`, `API`, `데이터셋`, `학습 데이터`를 요청하면 같은 사실 원장을 JSON 부록으로도 제공한다.
- 다른 AI에 넣을 마스터 프롬프트에는 사실, 금지된 추론, 동적 정보 경고를 모두 포함한다.
- 가격과 재고에는 기준일을 붙인다.

### 7. 구조 검증

Markdown 파일을 만들었으면 다음 검증기를 실행한다.

```bash
python3 scripts/validate_brief.py /absolute/path/to/product-ad-knowledge.md
```

검증이 실패하면 누락된 섹션이나 출처 분류를 보완하고 다시 실행한다. 검증 통과가 사실의 진위를 보증하지는 않으므로, 광고 주장은 별도로 증빙한다.

## 도구 선택과 정리

- 현재 탭의 일반 텍스트는 `getTabContext`를 먼저 사용한다.
- 상세 이미지·지연 로딩·옵션 DOM 확인에는 Chrome 제어를 사용한다.
- 로컬 이미지 파일은 시각 도구로 직접 읽는다.
- PDF 상세페이지는 PDF 스킬로 읽고 렌더링한다.
- 외부 웹 검색은 사용자가 요청했거나 페이지 주장 검증이 필요한 경우에만 사용한다.
- 브라우저로 연 탭과 내려받은 중간 이미지는 작업 종료 전에 해당 브라우저·환경 지침에 따라 정리한다.
- 사용자용 결과만 출력 폴더에 남기고 원본 이미지·OCR 중간물은 작업 폴더에 둔다.

## 완료 기준

다음을 모두 만족해야 완료다.

- 이미지 문구까지 포함해 페이지 전체를 확인했다.
- 본품과 추가상품이 분리됐다.
- 모든 본품 옵션의 총액과 단가가 정리됐다.
- 확인된 사실과 페이지 주장이 분리됐다.
- 동적 정보에 기준일이 있다.
- 광고 위험 표현과 누락 정보가 표시됐다.
- AI 마스터 프롬프트가 있다.
- 저장한 Markdown이 검증기를 통과했다.
