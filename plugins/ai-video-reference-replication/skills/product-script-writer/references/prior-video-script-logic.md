# 이전 영상 대본 논리 계승

새 레퍼런스가 들어올 때마다 제품 논리가 초기화되는 문제를 막기 위한 공통 절차다. 모든 업체와 제품에 적용한다.

## 출처 선택

`scripts/prior_video_script_logic.py`가 반환한 `selected_sources`를 모두 처음부터 끝까지 읽는다. 우선순위는 다음과 같다.

1. `product_context.md`의 `승인된 최근 대본 예시`가 가리키는 실제 파일
2. 정확한 제품 폴더의 `approved-script.txt` 계열 승인본
3. 정확한 제품 폴더의 CapCut 실사용 `input/대본.txt`
4. 영상·편집 매니페스트가 함께 있는 생성 결과물의 주 대본

동일 SHA-256 또는 동일 본문의 낭독용 표기본은 하나의 논리 출처로 취급한다. 다음은 제외한다.

- TTS 발음 교정 조각, `followup`, `cta` 전용, `supplement`, `preview`
- `rejected`, `폐기`, `사용주의`, 실패·중단 폴더
- 다른 업체, 같은 업체의 다른 제품, 업체 공용 대본
- 파일명만 최신이고 승인 또는 실제 영상 사용 근거가 없는 고립 초안

## 논리 프로필

선택한 대본에서 문구가 아니라 인과관계를 추출한다.

```json
{
  "hook": "시청을 멈추게 하는 첫 결론 또는 문제",
  "problem": "타깃이 겪는 핵심 불편",
  "cause": "문제가 생기는 제품별 원인 설명",
  "existing_solution_limit": "기존 해결책이 부족한 이유",
  "product_reveal": "제품을 공개하는 시점과 연결 문장",
  "mechanism": "성분·구조·사용 방식이 결과로 이어지는 논리",
  "result": "기대 결과와 변화",
  "proof_or_offer": "근거·사회적 증거·가격·혜택",
  "cta": "마지막 행동 유도",
  "must_preserve": ["최근 승인본에서 반복 승인된 인과관계"],
  "superseded": ["최신 정정으로 폐기된 이전 값 또는 논리"]
}
```

각 항목에는 근거가 된 파일 경로와 SHA-256을 내부적으로 연결한다. 여러 승인본이 있으면 최신 승인본을 기본으로 하고, 더 오래된 대본은 최신본에 없는 보조 단계만 제공한다. 최신 사용자 직접 정정은 모든 이전 대본보다 우선한다.

## 새 레퍼런스와 결합

- `prior_video_logic`은 제품의 인과관계다.
- 새 레퍼런스는 후킹 유형, 문장별 설득 역할, 제품 공개 시점, 반문·비교·보증·긴급성, 표현 강도, 문장 길이와 낭독 리듬이다.
- 두 층을 결합하되, 새 레퍼런스의 다른 제품 원인·성분·효과·CTA를 가져와 기존 제품 논리를 덮지 않는다.
- 레퍼런스 순서를 문자 그대로 적용하면 기존 제품 인과관계가 끊길 때는, 레퍼런스의 수사 역할을 가장 가까운 제품 논리 단계로 이동한다.
- 사용자가 새 소구나 새 논리를 명시하면 그 범위만 바꾸고 나머지 기존 논리는 유지한다.

가격·재고·할인·후기·혜택처럼 변하는 값과 과거 대본의 주장 상태는 현재 `product_context.md`의 구분을 그대로 따른다. 이전 영상에 사용됐다는 사실만으로 현재 사실이나 게시 승인 문구가 되지 않는다.

## 이전 대본이 없을 때

`status: no_prior_video_script`이면 현재 제품 컨텍스트와 사용자 입력으로 작성한다. 다른 업체나 제품의 대본 논리를 대신 가져오지 않고, 이전 대본이 없다는 이유만으로 이미 받은 입력을 다시 묻지 않는다.
