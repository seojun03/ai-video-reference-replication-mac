# 전체 실행 절차

## 목차

1. 작업 전 확인
2. 레퍼런스 처리
3. 보이스 선택과 저장
4. 대본 계획
5. coherent-block 생성과 자동 검수
6. 사용자 청취 승인 또는 강화 자동 QC 최종화 위임
7. 거절과 추가 생성
8. 최종 산출물
9. 복구와 중단

## 1. 작업 전 확인

다음을 확인한다.

- 사용자가 레퍼런스 음성의 복제·재사용 권한을 보유함
- 대본이 한국어이고 실제 읽을 문장이 확정됨
- 레퍼런스에는 한 명만 발화함
- 출력 폴더가 비어 있거나 존재하지 않음
- `ffmpeg`, `ffprobe`, Python, `requests`, `numpy` 사용 가능
- `ELEVENLABS_API_KEY` 환경변수 설정
- `doctor --live`에서 `eleven_v3` 확인

API 호출 전 대본에서 영문·숫자를 검사한다. 모호한 토큰이 있으면 사용자가 한글 발음을 확정할 때까지 중단한다.
모든 새 clone과 기존 보이스 재사용은 `--consent-confirmed`가 필요하며 확인 시각·사용 모드·레퍼런스 SHA-256을 작업 상태에 기록한다.

## 2. 레퍼런스 처리

새 clone과 외부 기존 보이스의 스타일 레퍼런스에는 같은 절차를 적용한다.

1. 영상에서 단일 채널 48kHz WAV를 파생한다.
2. ElevenLabs Audio Isolation으로 배경음악과 효과음을 줄인다.
3. 앞뒤 무음만 제거하고 내부 호흡과 자연스러운 쉼은 보존한다.
4. Scribe v2 화자 분리 전사로 한국어와 단일 화자를 확인한다.
5. 유효 발화 길이, 무음 비율, 클리핑, 평균 음절/초, 쉼, 피치 범위를 측정한다.
6. `reference/reference_profile.json`에 근거와 경고를 저장한다.

유효 발화가 20초 미만이거나 한글 발화량이 너무 적으면 clone을 만들지 않는다. 20~45초는 경고를 남기되 사용자가 1분 이내 레퍼런스를 사용하기로 한 현재 계약에 따라 진행할 수 있다.

Audio Isolation은 배경음과 효과음을 줄이지만 모든 흔적을 완전히 제거한다고 가정하지 않는다. 분리 결과의 클리핑·발화량 게이트를 반드시 적용한다.

## 3. 보이스 선택과 저장

### 새 보이스

- 분리된 WAV로 Instant Voice Clone을 만든다.
- 원본 영상에 다시 노이즈 제거를 중복 적용하지 않는다.
- 반환된 `voice_id`, 이름, 생성 시각, 소스 SHA-256, 스타일 프로필 경로를 저장한다.
- 로컬 레지스트리는 `~/.codex/state/elevenlabs-reference/voices.json`에 저장한다.
- API 키와 원본 음성 바이트는 레지스트리에 저장하지 않는다.
- `requires_verification=true`이면 계정 검증을 완료하기 전 TTS를 생성하지 않는다.

### 기존 보이스

- 정확한 `voice_id`를 우선한다.
- 이 스킬로 만든 clone이면 저장된 스타일 프로필을 사용한다.
- 프로필이 없는 보이스는 새 스타일 레퍼런스 영상 없이는 엄격한 속도·감정 일치를 약속하지 않고 중단한다.
- ElevenLabs의 `voice_verification`과 로컬 검증 대기 표시를 모두 확인하고, 검증 완료를 확인할 수 없는 보이스는 사용하지 않는다.

## 4. 대본 계획

원래 대본을 `input/script.txt`에 복사하고 수정하지 않는다.

이 로컬 사용자의 기본 자연 발화 프리셋이 활성화되어 있으면 60초 이하
생성용 대본은 원문 어휘를 바꾸지 않은 채 레이아웃용 줄바꿈과 빈 줄을
공백으로 정리해 한 문단의 연결 발화로 만든다. 문법상 필요한 문장부호는
보존하되 발음 교정을 위한 과도한 쉼표·대시·마침표는 추가하지 않는다.

문장별로 다음을 `script_plan.json`에 기록한다.

- 원문
- 실제 발화문
- Eleven v3에 전달할 감정·속도 태그 포함 문장
- 자동 또는 사용자 지정 전달 방향
- 모든 생성 시도와 seed
- 자동 검수 결과
- 집중 발음 구절과 3회 반복 전사 결과
- 선택된 후보
- 사용자 피드백과 승인

사용자 태그가 있으면 자동 감정보다 우선한다. 태그가 없으면 문장 의미와 레퍼런스의 전체 에너지에 따라 감정을 선택한다. 원래 단어를 감정 표현을 위해 추가·삭제하지 않는다.

이 워크플로우에서 “레퍼런스와 같은 감정”은 다음을 목표로 한다.

- 같은 전체 말투, 에너지, 평균 속도 성향
- 새 대본 의미에 맞는 문장별 감정
- 사용자가 지정한 감정 태그 우선

자동 분석은 속도·피치·쉼 측정과 문장 키워드 휴리스틱이다. 새 대본과 레퍼런스의 문장 내용이 다르므로 레퍼런스의 순간별 감정 곡선이나 호흡을 그대로 복사했다고 주장하지 않는다. 기본 경로에서는 최종 감정·억양 적합성을 사용자가 듣고 판정한다. 사용자가 청취를 명시적으로 생략하고 강화 자동 QC 최종화를 위임한 별도 경로에서는 이 항목을 확인 완료로 표현하지 않고 자동 검수의 한계로 남긴다.

## 5. coherent-block 생성과 자동 검수

1분 이하 단일 화자 대본은 문장별로 독립 생성하지 않는다. 전체 대본을
한 번의 Eleven v3 요청으로 만들어 seed·stability·speed·보이스 설정을
동일하게 유지한다. 사용자 태그가 없으면 레퍼런스 전체 전달 성향에서
정한 전역 태그 하나만 사용하며, `?`와 `!`를 이유로 문장별 태그를 자동
교체하지 않는다.

현재 로컬 기본 프리셋은 `natural_v3_conversational_coherent`다. 사용자가
현재 작업에서 다른 값을 명시하지 않으면 `model_id=eleven_v3`, 전역 태그
`conversationally`, API `speed=1.15`, `stability=0.35`를 사용한다. 보이스별
음색과 화자 캐릭터는 각 레퍼런스에서 가져오되, 전달 방식은 사람처럼
이어 말하는 한 번의 coherent take로 통일한다. v3를 사용할 수 없으면
v2로 조용히 낮추지 않는다.

초기 배치는 다음 절차를 정확히 한 번 수행한다.

1. 전체 대본을 Eleven v3 응답 하나로 생성
2. 응답 원본을 48kHz mono WAV와 MP3로 변환
3. Scribe v2로 전체 한국어 재전사하고 원래 전체 발화문과 정확 비교
4. 재전사·언어 하드 게이트 통과 시에만 전체 Forced Alignment 실행
5. 정렬 시각으로 문장별 리뷰 WAV·MP3를 파생하되 원래 take는 수정하지 않음
6. 문장별 STT·정렬·집중 발음·평균 속도·무음·클리핑 검사
7. 전체 원본 take에 레퍼런스 보정형 피치·에너지·리듬·문장 경계 검사
8. 실제 오디오 입력 평가 수단으로 레퍼런스와 생성본 A/B 판정 3회
9. 하나라도 실패하면 일회용 내부 재시도 토큰을 발급하고 남은 take 한도에서 교정 재생성

이 로컬 사용자는 활성 요청 범위 안의 전체 take를 작업당 총 5개까지
상시 허용했다. 사용자의 별도 비용 승인을 묻지 않고 현재 내부 토큰을
`coherent_block.py retry`에 전달한다. 토큰은 TTS 호출 전에 소진한다.
retry는 전체 대본 요청 하나만 실행하며, 실패하면 새 내부 토큰으로 다음
교정 take를 이어서 만들 수 있다. 속도는 직전 후보와 레퍼런스의 평균
발화율 차이로 0.7~1.2 안에서 보정하고 seed·stability는 기록한다.

집중 발음 구절은 전체 Forced Alignment 결과에 정확히 한 번 나타나야
한다. 인접 단어는 제외하되 바로 앞 공백·문장부호 경계를 포함해 초성을
보존하고, 문장 끝 구절은 실제 파생 클립 끝까지 보존한다. 같은 크롭을
`seed=173, temperature=0.0`, `seed=907, temperature=0.1`,
`seed=2027, temperature=0.2`로 각각 전사해 세 결과가 모두 정확해야 한다.
측정 불가 또는 다수결은 실패다.

전체 take 원본을 `review/full_preview.wav`와 MP3로 보존한다.
`review/segments/NNN.*`는 검수와 사용자 탐색용 파생 클립일 뿐이며 이를
다시 이어 붙여 coherent 미리보기를 만들지 않는다. 최종 WAV도 승인된
원래 take PCM을 사용한다.

초기 1회와 교정 retry를 합쳐 최대 5개 전체 take만 생성한다.
API 또는 QC 호출 자체가 실패하면
불필요한 TTS를 더 만들지 않고 즉시 멈춘다. 60초를 넘는 작업만 의미
단락별 coherent block으로 나누며, 블록 경계에도 같은 연결성 게이트를
적용한다.

## 6. 사용자 청취 승인 또는 강화 자동 QC 최종화 위임

### 기본 경로: 사용자 청취 승인

모든 문장 자동 검수, 전체 운율·경계 검사, 실제 오디오 A/B 3회가
통과하면 coherent take의 전체 미리보기를 사용한다.

- `review/full_preview.wav`
- `review/full_preview.mp3`

전체 미리보기와 필요하면 문장별 MP3를 사용자에게 재생한다. 사용자의 명시적 응답을 기다린다.
승인은 `status`의 현재 `preview_sha256`과 연결하며 전체 문장을 한 번에 승인한다. 미리보기 파일이 없거나 해시가 바뀌었거나 작업 상태가 승인 대기가 아니면 승인 명령이 실패해야 한다.

승인으로 인정할 수 있는 예:

- “전체 들어봤고 괜찮아”
- “이대로 승인”
- “발음과 감정 모두 확인했어”

단순히 “진행해”, 파일을 확인하지 않은 상태의 추정, 자동 검수 통과 사실은 청취 승인이 아니다.

### 별도 경로: 명시적 강화 자동 QC 최종화 위임

사용자는 전체 미리보기를 직접 듣지 않겠다고 명시하고, 강화 자동 QC만을
근거로 최종화를 위임할 수 있다. 이 경로는 추정하거나 기본값으로 선택하지
않으며 다음 확인 문구가 정확히 기록된 경우에만 `delegate-approve`를
사용한다.

```text
사용자가 전체 미리보기 직접 청취를 생략하고 강화 자동 검증 기반 최종화를 위임함
```

`delegate-approve`도 현재 전체 미리보기의 SHA-256과 모든 리뷰 파일
해시에 묶이며, 모든 문장의 일반 자동 게이트와 설정된 모든 집중 발음
게이트가 통과됐는지 증거 파일까지 다시 확인한다. 레퍼런스 보정형
운율·문장 경계 검사와 실제 오디오 A/B 3회 만장일치 증거도 현재
레퍼런스·미리보기·문장별 WAV 해시와 일치해야 한다. 이어 전체 미리보기
WAV를 새로 전사하고, 한글·어휘·언어가 모두 정확할 때만 새 Forced
Alignment를 실행해 전체 대본과 시각 정렬이 완전한지 확인한다. 이 모든
검사가 통과된 경우에만 최종화한다. 최종 `job.json`과
`qc_report.json`에는 다음을 사실대로 기록한다.

전체 미리보기와 최종본은 각 문장 WAV를 mono·48kHz·24-bit PCM으로
개별 정규화한 뒤 PCM 프레임을 순서대로 이어 붙인다. 비트 심도가 다른
입력을 concat demuxer에 직접 넘기지 않으며, 결과 총 프레임 수와 PCM
해시가 정규화된 문장별 PCM 순서와 다르면 기존 파일을 바꾸지 않고
실패 처리한다.

장문 전체 미리보기 전사가 정확 일치하지 않더라도 비어 있지 않은
한국어인 경우에만 문장 단위 보조 검증 후보가 된다. 장문 전사의
누락·치환 여부는 진단으로 보존한다. 선택된 문장별 WAV를 각각 공통
PCM으로 독립 디코딩해 순서대로 누적한 프레임 수·해시와 실제
미리보기의 공통 PCM 프레임 수·해시가 완전히 같아야 한다. 실제
미리보기의 형식·클리핑·활성 음성도 하드 게이트다. 이어 모든
문장별 WAV를 서로 다른 설정으로 3회 새로 전사해 세 결과가 모두
정확해야 하며, 그때만 새 Forced Alignment를 실행한다. 한 검사라도
실패하면 최종화하지 않는다.

- 상태: `user_delegated_auto_qc_final`
- `approval_type`: `delegated_automatic_qc`
- `human_listening_completed`: `false`

이 경로를 사람 청취 승인으로 기록하거나 표현하지 않는다. 자동 STT,
강제 정렬, 집중 발음 3회 합의는 자연스러움·감정·억양·목소리 동일성을
완전히 보증하지 못하며, 이 한계를 최종 보고서와 사용자 전달문에
명시한다.

## 7. 거절과 추가 생성

사용자가 문장에 품질 피드백을 주면 다음을 기록한다.

- 문장 번호
- 어색한 단어 또는 구간
- 발음, 속도, 감정, 쉼 중 문제 유형
- 원하는 방향

기존 문장별 호환 모드에서는 문제가 있는 문장만 `regenerate`한다. coherent
모드에서는 한 문장 실패도 전체 take 재생성 사유이며 부분 교체를 하지
않는다. 전체 take는 최대 5회이며 이 한도를 늘리는 추가 배치는 지원하지
않는다. 현재 `status`가 발급한 `additional_generation_token`은 에이전트가
내부적으로 전달한다. 토큰은 TTS 요청 전에 한 번 사용하면 즉시 소진되며,
다음 전체 take에는 새 내부 토큰을 사용한다. 사용자에게 승인 질문을 하지 않는다.

발음 문제는 알려진 붙임말 발음 사전, seed·stability 변경, 자연스러운
문법 경계만 조정한 전체 대본 `--tts-override` 순서로 해결한다. 단어·음절
분리, 문장별 splice, 빈 줄이나 과도한 문장부호로 인위적 쉼을 넣는 방식은
사용하지 않는다. 원래 발화문은 검수 기준으로 계속 보존한다.

새 take가 통과하면 그 원본으로 전체 미리보기를 교체하고 다시
운율·오디오 3회 검수를 수행한다. 이전 승인과 보고서는 새 미리보기에
자동 승계하지 않는다.

사용자가 보존된 이전 후보를 선호하면 `select-attempt`로 그 후보의 기존
WAV·MP3를 재사용한다. 현재 STT 표기 정규화와 Forced Alignment, 속도,
무음, 클리핑 게이트를 다시 통과한 경우에만 문장 선택본으로 복원한다.
집중 발음 구절이 설정된 문장은 강제 정렬로 비고유하지 않은 위치를 다시
찾고, 인접 단어를 제외한 비어휘 경계 포함 크롭과 앞뒤 0.2초 무음, 지정된 seed·temperature
3조합의 Scribe 전사까지 새 후보와 동일하게 다시 통과해야 한다. 측정할
수 없거나 구절 위치가 비고유하면 이전 후보를 선택하지 않는다.
이 선택은 문장 후보에만 적용되며 전체 미리보기 최종 승인으로 간주하지
않는다.

## 8. 최종 산출물

사용자 청취 승인 뒤 `approve`를 실행하거나, 사용자의 명시적 위임 뒤
`delegate-approve`를 실행한 경우에만 다음을 만든다.

```text
final/
├── final.wav
├── final.mp3
├── script.txt
├── qc_report.json
└── segments/
    ├── 001.wav
    ├── 001.mp3
    └── ...
```

WAV는 영상 편집 호환성을 위해 mono 48kHz PCM으로 저장한다. API 계정이 Pro 이상이면 44.1kHz PCM 소스에서 변환하고, Creator면 192kbps MP3 소스, 그 아래 요금제면 128kbps MP3 소스에서 파생된다. 소스 형식의 한계를 품질 보고서에서 숨기지 않는다.

`approve`로 만든 보고서는 실제 청취 승인을, `delegate-approve`로 만든
보고서는 청취 생략과 자동 QC 위임을 서로 다른 상태·승인 유형으로
기록한다. 두 경로를 같은 사람 청취 승인으로 합치지 않는다.

## 9. 복구와 중단

- 기존 출력 폴더를 새 작업으로 덮어쓰지 않는다.
- `job.json`과 `script_plan.json`을 근거로 현재 상태를 확인한다.
- 중단된 작업에 새 `run`을 실행하지 않는다. `status`, `regenerate`, `approve`, `delegate-approve` 중 현재 상태와 사용자의 명시적 선택에 맞는 명령만 사용한다.
- 자동 게이트 실패는 품질 실패이지 최종 실패가 아니다. 후보와 사유를 보존하고 사용자에게 다음 선택을 요청한다.
- 사용자 청취 승인이나 명시적 자동 QC 최종화 위임이 없는 작업은 `awaiting_user_listening_approval` 상태로 유지한다.
- 작업 폴더에는 레퍼런스 파생 파일, 전사와 실패 후보가 남는다. 폴더 권한은 사용자 전용으로 만들며, 최종 완료 뒤 삭제 여부는 사용자에게 맡긴다.
