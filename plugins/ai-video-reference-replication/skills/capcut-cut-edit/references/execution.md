# 컷편집 실행 연결

이 문서는 실제 분석·저장 경로를 고를 때만 읽는다. 컷 기준·자막 선택·숫자 기본값은 `../SKILL.md` 한 곳에서 관리한다. 여기에 별도 편집 기본값을 누적하지 않는다.

## 문맥별 모드의 전용 연결

대본·클린본·사용자 음성을 조합하는 요청은 [문맥별 스킬](../../capcut-semantic-cut-edit/SKILL.md)의 [전용 실행](../../capcut-semantic-cut-edit/references/execution.md)을 쓴다. 이 요청에 한해서 새 대상이 고정된 `semantic_cut.py`의 `bind → stage → install → verify` 경로가 있다. 입력 장면/음성/기본 자막을 새로 조합하는 좁은 저장기이며, 일반 컷편집의 기존 타임라인 효과/스타일 보존 편집을 대신하는 범용 엔진이 아니다.

[제품 종류 인터뷰](../../capcut-semantic-cut-edit/references/visual-direction.md)의 응답을 받은 뒤 해당 분야의 **화면 연출 프로필만** 사용한다. 자막·호흡·무음·싱크·공통 컷 기준은 `../SKILL.md` 그대로이며 분야 프로필의 학습/적용으로 수정하지 않는다. 저장용 `source_id`는 편집 레퍼런스가 아니며, `resolve-project`/`bind`가 현재 업체 프로젝트의 기술 형식만 자동 연결한다. 문맥별 모드에서 기준 타임라인·새 타임라인 이름을 필수 사용자 입력으로 요구하지 않는다. 기본 자막·무음 컷·원본 보존·새 타임라인 1개는 이 모드에 포함된다.

아래 레거시 `talking-head`·`voiceover`의 `RUN_CONTEXT_TARGET_BINDING_REQUIRED` 차단은 그대로 유지한다. 새 스킬이 있다는 이유로 그 차단을 해제하거나 하위 명령으로 우회하지 않는다. 문맥별 모드가 아닌 작업에는 아래 기존 제한을 적용한다.

## 분리 범위

이 패키지는 `capcut-automation`의 컷편집 지침을 독립적으로 편집하기 위한 분리본이다. 원본 스킬을 실행하거나 원본 설정을 덮어쓰지 않는다. 엔진 코드 전체나 독립 타임라인 저장기를 복제한 것은 아니다.

2026-08-30 확인한 로컬 엔진은 `${CAPCUT_AUTOMATION_ROOT}`다. 실제 실행 시 경로와 함수·명령의 현재 동작을 다시 확인한다. 다른 컴퓨터에서 이 경로가 없으면 원본을 찾았다고 추정하지 않는다.

## 현재 실행 제한

- 원본 스킬의 `scripts/run_capcut_automation.py`는 `talking-head`·`voiceover`의 실제 쓰기를 `RUN_CONTEXT_TARGET_BINDING_REQUIRED`로 막는다. 정확한 기존 프로젝트·소스 타임라인·새 대상 연결을 지원하지 않기 때문이다. `--dry-run`은 명령을 출력할 뿐 편집하지 않는다.
- 원본 보이스오버 검증은 스타일·폰트 인터뷰를 요구한다. 이 분리본의 자막 선택이나 스타일 미적용을 원본 엔진이 그대로 지원한다고 가정하지 않는다.
- `python -m capcut_auto`, `create_capcut_draft`, 레거시 설치 스크립트를 직접 호출해 위 차단을 우회하지 않는다. 다른 업체·과거 작업에 고정된 설치 스크립트도 재사용하지 않는다.
- `compile_hybrid_capcut_timeline.py`는 기존 초안을 기반으로 하는 별도 경로다. 파일명이 비슷하다는 이유로 임의 컷 재배치와 동일 기능이라고 간주하거나 바로 실행하지 않는다.
- **이 분리본에는 새 범용 저장 adapter가 포함돼 있지 않다.** 호환되는 안전 실행 경로를 확인하지 못하면 읽기 전용 조사와 전용 작업 폴더의 컷 계획까지 진행하고, 타임라인 생성은 미실행으로 보고한다. 실행기 추가·변경은 사용자가 요청한 범위에서 별도로 다룬다.

## 분석 모듈의 재사용 범위

필요한 기능만 확인한다. 엔진의 전체 기본값·스타일·효과음·제품 피드백을 불러와 새 스킬의 기준을 다시 덮어쓰지 않는다.

| 용도 | 확인할 기존 코드 |
|---|---|
| 원본 길이·해상도·FPS 확인 | `capcut_auto/media.py` |
| 단어 전사와 타임코드 | `capcut_auto/transcribe.py` |
| 말하는 영상의 무음·말버릇·반복 후보 | `capcut_auto/editing.py`, `capcut_auto/config.py` |
| 별도 음성의 내부 호흡 구간 편집 | `capcut_auto/voice_silence.py` |
| 최종 음성의 파형 경계 분석 | `capcut_auto/waveform_sync.py` |
| 최종 음성 증거 검증 | `capcut_auto/voice_delivery_gate.py` |

이 표는 구현 위치 안내이며 해당 함수를 안전 확인 없이 실행하라는 뜻이 아니다. 원본을 입력과 출력에 동시에 지정하지 않고, 결과는 새 작업 폴더에만 쓴다. 전사는 모델 로컬 캐시 여부를 확인하며 필요하지 않은 모델 다운로드나 외부 전송을 하지 않는다.

레거시 분석기의 기본값이 공통 `SKILL.md`와 다르면 제공되는 분석 인자로 공통 기준을 전달하거나 후보를 별도로 검토한다. 과거 기본값을 그대로 최종 컷 기준으로 쓰거나 원본 엔진 설정을 덮어쓰지 않는다. 문맥별 분석기의 `recorded` 후보가 이전 0.2초 여유를 제안해도 삭제 승인이나 최종 타이밍으로 채택하지 않는다. 현재 음성의 실제 발화 경계·문맥을 확인해 공통 스킬의 짧은 연결 여유로 계획하고, 완성 음성의 잔여 쉼을 다시 검토한다.

## 파형·컷·자막 검증

- 삭제 후보는 단어 타임코드만 보고 확정하지 않는다. 현재 음성의 파형과 문맥을 함께 확인한다. 불확실한 말실수·의도적 반복은 남기고 보고한다.
- ASR 단어 시각은 탐색 기준이다. 모든 자막의 실제 시작 프레임은 현재 최종 음성에서 첫 발음이 시작되며 파형이 커지는 지점으로 확인한다. 호흡·저주파 잔류음·잡음, 발음의 작은 첫 자음, 뒤의 큰 모음 최고점을 구분한다. 분석이 모호하면 근거 없이 글자 수 비례나 옛 타임스탬프를 쓰지 않는다.
- `SKILL.md`의 발화 시작 기준을 적용한다. 원본 검수 문서에 함께 있는 '저에너지 골 프레임'과 '발성 상승 프레임'을 서로 같은 정의로 취급하지 않는다. 검증기가 다른 기준을 강제하면 검사 결과를 조작하지 말고 불일치를 보고한다.
- 최종 음성 SHA-256과 그 음성으로 만든 컷·자막 계획을 함께 기록한다. 변경 전 음성에서 만든 계획을 완료 증거로 쓰지 않는다.
- 각 자막의 첫 발음 검토와 영상/자막 컷 0프레임 일치 검사를 구분해 둘 다 수행한다. 한 번 발견한 4프레임 차이를 모든 자막에 더하거나, 새 작업마다 쉼을 4프레임 더 자르지 않는다. 승인된 호흡감은 공통 기준의 현재 음성별 판단으로 재현한다.
- 최종 전체 전사에서 단어가 빠지면 원본·편집 음성의 해당 구간을 비교한다. 필요하면 정확히 잘라낸 최종 구간을 예상 문구로 유도하지 않고 별도로 전사하여 누락 여부를 확인한다. 전체 전사 불일치와 구간 검토 근거를 함께 기록하고, 인식기가 빠뜨린 문구를 자막에서 지우거나 음성을 결과에 맞춰 조작하지 않는다.
- 타이밍은 프로젝트의 실제 FPS를 기준으로 프레임에 맞춘다. 프레임 시각을 마이크로초로 저장할 때는 다음 프레임으로 밀리지 않도록 내림 처리한다. 30fps의 반복소수 프레임은 특히 확인한다.
- 각 컷의 실제 원본 절대 경로·SHA-256·source 시작/끝과 target 시작/끝을 확인한다. 다른 의미 섹션에서 같은 소스를 재사용하려면 그 의도와 구간이 현재 계획에 명시돼 있어야 한다.
- 효과 등을 위해 연속 분할된 같은 소스는 source 시간이 이어져야 한다. 재시작·중복·누락을 허용하지 않는다.
- 클린본은 원본이나 byte-identical 사본만 연결한다. 프록시·재인코딩·FPS 변환·업스케일·프레임 보간으로 대체하지 않는다. 단순 컷편집은 원래 화면비·crop·transform을 유지한다.
- 선언된 짧은 소스의 꼬리 공백을 제외한 공백·겹침은 실패다. 꼬리 공백이 있다면 다음 컷의 제시간 배치를 확인하고 `config.maintrack_adsorb=false`가 유지되는지 검사한다.
- 자막을 포함할 때만 자막 검사를 실행한다. 선택 폰트의 실제 폭·줄 수·문법·발화 순서와 프레임 경계를 저장본에서 확인한다. 기본 폰트가 없으면 임의 폰트 ID를 만들지 말고 누락을 보고한다.

## CapCut에 실제로 쓸 수 있는 경로의 요건

1. 요청한 기존 업체 프로젝트를 이름·절대 경로·프로젝트 식별자로 정확히 고정한다. 없거나 여러 개면 임의 프로젝트를 만들거나 대신 쓰지 않는다.
2. 소스 타임라인, 새 대상 이름/ID, 작업 출력 경로와 원본 지문을 쓰기 전에 고정한다. 기존 타임라인 ID와 새 대상이 같으면 거부한다.
3. 원본 미디어와 기존 타임라인의 파일 지문을 기록한다. 등록용 프로젝트 색인은 별도로 백업하고 허용된 새 타임라인 추가만 비교한다. 등록 때문에 필요한 색인 변경과 기존 타임라인 변경을 혼동하지 않는다.
4. CapCut 실행 상태와 프로젝트 잠금을 모두 확인한다. 앱이 실행 중이면 [공통 자동 저장·정상 종료 절차](../SKILL.md#실행-중인-capcut의-자동-저장정상-종료)로 현재 작업을 보존하고 직접 정상 종료한다. 사용자에게 종료나 종료 승인을 요청하지 않는다. 앱 종료와 잠금 해제가 모두 확인된 뒤에만 쓴다. 강제 종료·잠금 삭제를 하지 않는다.
5. 엔진이 요구하는 run contract·hash·대상 결합을 검증한다. 계약 실패를 스타일 선택 조작, 승인 기록 생성, 검사 삭제, 임의 수정된 공통 계약으로 통과시키지 않는다.
6. 새 타임라인과 필요한 미디어만 고유 경로로 추가한다. 기존 결과 overwrite·삭제·원본 이동·원본 이름 변경은 하지 않는다. 기존 레시피·registry·학습 기록에 쓰지 않는다.
7. 등록 직전 다시 source freshness·대상·앱 상태를 확인한다. 경로가 이 보호를 제공하지 않으면 그대로 실행하지 않는다.
8. 저장된 타임라인에서 영상·음성·선택 자막의 실제 source/target 구간, material 연결, 소스 파일 존재와 지문을 읽어 비교한다. 의도한 컷과 자막 시작은 0프레임 오차여야 한다. 의미 섹션 내부의 표시 자막 분할은 영상 컷으로 세지 않는다.
9. 새 타임라인 등록 여부와 기존 타임라인·원본 불변성을 다시 확인한다. 파일만 만들어진 상태나 임시 staging은 편집 완료가 아니다.

현재 작업의 저장 확인·정상 종료를 위한 최소한의 앱 제어만 공통 절차에 따라 수행한다. 그 외 GUI 편집·청취·영상 export는 이 스킬의 작업에 포함하지 않는다. 저장·종료 확인을 영상 재생 검수로 기록하지 않는다.

## 원본과의 관계

- 추출 근거: 원본 스킬의 `references/modes/base-cut.md`, `references/manifest-format.md`, `references/quality-check.md`, 클린본 무결성·컷 순서 문서와 로컬 `contracts/editing-core.json`.
- 원본에서 유지: 의미 보존, 무음·호흡 정리, 최종 음성 기준 싱크, 한 줄 자막, 소스 무결성, 기존 결과 보호, 새 편집 가능 타임라인, 저장본 역검증.
- 분리하며 제외: 필수 스타일 인터뷰, 기본 효과음 라우팅, 레퍼런스 모사·스타일 학습·자동 피드백, 강제 3:4 프레이밍과 확대. **일반 컷편집과 문맥별 모드 모두 대화 자막을 기본 포함**하며 명시적 제외 요청은 따른다. 자막 포함 여부를 필수 질문으로 만들지 않는다.
- 원본 문서·공통 계약의 향후 변경을 자동 상속하지 않는다. 이 분리본의 기본값 변경은 사용자가 요청한 경우에만 `SKILL.md`에 반영한다.
- 위 제외는 엔진의 안전 게이트를 해제하는 설정이 아니다. 기존 엔진과 맞지 않는 지점은 별도 실행기 연결 문제로 보고한다.
