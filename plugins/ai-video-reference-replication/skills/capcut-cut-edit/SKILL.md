# CapCut 컷편집

**공통 음성·컷·자막 기준은 이 파일에서만 관리한다.** 제품 종류별 학습은 클린본의 **장면 선택·배치·구도**에만 적용한다. 내부 저장·검수는 [실행 연결](references/execution.md), 화면 연출은 아래 문맥별 모드에 분리했다.

## 전역 기본 호출

2026-09-07 사용자가 **실제 발음 시작 기준의 컷·자막 재정렬 결과**를 전역 컷편집 방식으로 승인했다. `컷편집 해줘`, `컷편집해줘`, `이 영상 컷편집`만으로 이 스킬을 적용하며, 브랜드·제품·새 채팅·호출 스킬에 따라 음성·쉼·자막 기준을 바꾸지 않는다. 기본 결과는 **자연스러운 의미구 컷 + 짧은 불필요한 쉼 + 실제 발음에 맞춘 대화 자막 + 새 편집 가능한 CapCut 타임라인**이다. 효과음·BGM·장식 연출·내보내기는 포함하지 않는다.

일반 컷편집에서 스타일·폰트·자막 포함 여부를 다시 묻지 않는다. 자막은 기본 포함하고 기존 디자인이 있으면 유지하며, 새 자막은 아래 기본 디자인을 사용한다. 사용자 명시 제외·별도 스타일·변경 범위는 우선한다. 승인 경위나 수동 기준의 해석이 필요할 때만 [승인된 발음 시작 편집 방식](references/approved-onset-style.md)을 읽는다. 사례의 고정 시각·총 길이·컷 수·4프레임 추가 삭제를 새 작업의 숫자로 복사하지 않는다.

기존 `capcut-automation`에서 컷편집 지침을 가져온 독립 문서다. 그 원본 스킬·레시피·업체별 학습 규칙을 자동으로 불러오거나 고치지 않는다. 실행 엔진 자체를 복제한 패키지는 아니므로, 실제 CapCut 저장 전에는 실행 연결 문서를 확인한다.

## 입력에 따른 실행 분기

- **대본 + 기존 클린본 + 사용자 음성을 조합하는 요청**, 또는 문장 문맥에 맞는 제품 장면 배치 요청이면 먼저 [제품 종류 인터뷰](../capcut-semantic-cut-edit/references/visual-direction.md)를 확인한다. 선택값은 **1. 건기식 / 2. 뷰티 / 3. 식품 / 4. 그외**다. 이번 작업에서 사용자가 종류를 직접 선택하지 않았다면 제품명으로 추정하지 않고 종류 하나만 물어 응답을 기다린다. 프로필 선택·자료 분석·편집 준비는 그 뒤에 시작한다.
- 상위 `ai-video-reference-replication`의 `production_intake`가 있으면 이번 답변의 `capcut.category`와 원문, 비율, 음성, 폰트, 편집 요청을 그대로 승계한다. 같은 분야·편집 여부·스타일/폰트 질문을 반복하지 않는다. 번호만 재해석하지 않으며, 정규화된 과거 선택도 바꾸지 않는다. 이 승계는 음성·소스·저장 검증의 생략을 허용하지 않는다.
- 종류가 확정되면 [문맥별 컷편집](../capcut-semantic-cut-edit/SKILL.md)으로 연결한다. 사용자가 별도 스킬을 다시 호출할 필요는 없다. 등록된 **화면 연출 프로필만** 새 채팅에서도 불러오며 자막·호흡·무음·싱크·공통 컷 기준은 이 파일 그대로 쓴다.
- **기준 타임라인 이름, 자막 포함 여부, 새 타임라인 생성 지시·이름은 이 모드의 필수 사용자 입력이 아니다.** 승인 사례를 매번 열어 재분석하지 않는다. 저장할 업체 프로젝트만 명확히 확인하고 저장 형식은 도구가 그 프로젝트 안에서 자동 연결한다.
- 그 모드는 9:16·150% 미만 보정·구간 단위 앞/뒤 재사용·클린본 원음 음소거·기본 자막을 포함한다. 이 파일의 공통 음성/자막 기준을 쓰되, 기존 소스 순서 유지와 확대/크롭 금지 대신 문맥별 모드의 명시된 장면 규칙을 적용한다.
- 이미 정해진 영상/타임라인의 단순 무음·말실수 정리나 자막 싱크만 요청하면 아래 **일반 컷편집**을 유지한다. 분야별 모드 때문에 기존 음악·구도·자막을 임의 변경하지 않는다.
- **단순한 “컷편집해줘”는 일반 컷편집을 기본으로 한다.** 제공된 발화 영상이나 기존 타임라인의 쉼·자막을 정리할 때 제품 종류 인터뷰를 시작하지 않는다. 제품 장면을 새로 선택·배치하는 요청이 명확할 때만 위 문맥별 모드의 종류 인터뷰를 적용한다. 이번 작업에서 이미 답한 종류는 재질문하지 않으며 과거 업체 기록만으로 새 장면 배치의 종류를 대신 선택하지 않는다.
- 스킬 설명/수정 요청이면 지침 작업만 한다. 실제 영상 편집을 자동 시작하지 않는다.

## 일반 컷편집에서 하는 일과 하지 않는 일

- 한다: 불필요한 무음, 명확한 말실수·말버릇·연속 반복 정리, 자연스러운 연결, 영상·음성 싱크, 기본 대화 자막 생성·싱크. 자막을 명시적으로 제외한 요청은 따른다.
- 하지 않는다: 대본 재작성, TTS 생성·교체, 효과음·BGM 추가, 스타일 적용, 레퍼런스 모사, 효과·전환·애니메이션 추가, 확대·크롭·화면비 변경, 학습·규칙 자동 승인, 내보내기.
- 기존 소스에 포함된 음악·효과·구도는 컷편집을 이유로 새로 디자인하거나 삭제하지 않는다. 컷 제거에 따라 연결된 구간을 함께 잘라 싱크를 유지하는 변경만 한다.

## 일반 컷편집을 시작할 때

- 사용자가 이 스킬의 지침을 읽거나 고쳐 달라고 하면 지침 작업만 한다. 영상 위치나 편집 스타일을 인터뷰하지 않는다.
- 실제 영상 편집 요청이면 **원본 위치와 정확한 저장 프로젝트**를 이번 입력·대화에서 확인하고, 실제로 빠진 값만 한 번에 묻는다. 제품 구분이 결과에 필요한 작업만 제품명을 확인한다. 대본이 없는 발화 영상은 현재 음성을 전사하며 대본 제출을 필수 조건으로 만들지 않는다.
- 기존 타임라인을 소스로 쓰면 그 타임라인을 정확히 확인한다. 최근 파일이나 다른 업체 작업을 대신 선택하지 않는다.
- 자막은 기본 포함한다. 기존 자막이 있으면 원문·디자인을 보존해 시작과 끝을 맞추고, 없으면 실제 음성으로 기본 자막을 만든다. 명시적 `자막 없이`는 새 자막 생성을 제외하며 기존 자막 삭제까지 뜻하지 않는다.
- 편집 스타일과 폰트를 다시 묻지 않는다. 별도 지정이 없으면 승인된 이 편집 방식과 아래 기본 폰트를 쓴다.
- 작업 ID와 새 타임라인 이름은 충돌하지 않게 생성한다. 사용자가 이미 지정한 값은 다시 묻지 않는다.

## 내가 고치는 컷편집 기준

현재 작업의 명시 지시가 이 표보다 우선한다. 작업별 예외는 이 파일의 기본값으로 자동 저장하지 않는다.

| 항목 | 기준 |
|---|---|
| 내용 보존 | 필요한 발화·의미·정보 순서를 유지한다. 말실수인지 불명확하면 삭제 후보로만 남긴다. |
| 말버릇·반복 | 의미 없는 망설임과 실수로 반복한 발화만 정리한다. 의도적인 강조 반복·감탄사·문맥상 필요한 단어는 남긴다. |
| 실제 말하는 영상의 긴 쉼 | 문장·완결된 의미구 사이의 불필요한 쉼이 0.5초 이상이면 정리 후보로 본다. 연결 여유는 약 0.1초 안팎을 탐색 시작값으로 삼고 현재 파형에서 앞 발화 끝·다음 첫 자음을 보존하는 짧은 연결로 정한다. 이전의 약 0.2초 여유를 일괄 유지하지 않는다. 이미 짧은 쉼, 문장 안의 자연스러운 호흡, 의도적인 질문·강조 쉼은 숫자만으로 더 자르지 않는다. |
| 쉼의 측정 | 자막·ASR 구간 끝이 아니라 실제 마지막 발화음부터 다음 발화음 시작까지 파형과 문맥으로 확인한다. 작은 말소리·끝음절·받침을 무음으로 취급하지 않는다. |
| 발음 시작 판단 | 해당 문구의 첫 발음이 시작되며 파형이 뚜렷하게 커지는 상승 지점을 현재 음성에서 찾는다. 발음 전 숨소리·저주파 잔류음·잡음 때문에 미리 시작하거나 큰 모음의 최고점까지 늦추지 않는다. 작은 첫 자음·마찰음도 발음이면 포함한다. ASR 시각은 탐색용이며 시작점 확정 근거를 대신하지 않는다. |
| TTS의 내부 호흡 | 0.20초 이상 공백을 편집 후보로 보고 총 0.10초를 남긴다. 세그먼트 사이뿐 아니라 세그먼트 내부도 확인한다. |
| TTS의 앞뒤 무음 | 감지 기준 -42dB, 최소 연속 무음 0.03초. 첫소리 앞 0.02초, 마지막 소리 뒤 0.05초 안전 여유를 둔다. 실제 발화 영상에 이 TTS 수치를 일괄 적용하지 않는다. |
| 의도적인 쉼 | 강조·질문·장면 구분에 필요한 쉼은 보존한다. 보존할 구간과 이유를 컷 계획에 적는다. |
| 목소리 | 원래 발화를 그대로 자르고 잇는다. 속도·피치 변경, 부분 배속, 다른 테이크 혼합, 말끝 잘라내기를 하지 않는다. |
| 컷 지점 | 완결된 의미구를 기준으로 자연스럽게 연결한다. 첫음절·끝음절·조사·수식어를 잘라내지 않는다. |
| 영상·음성 연결 | 편집된 최종 음성의 실제 발화 시작 프레임에 대응 영상 컷을 맞춘다. 앞 영상의 짧은 꼬리를 남기지 않는다. |
| 영상 선택 | 승인된 소스·순서를 유지한다. 실제 사용할 시작·중간·끝 프레임을 확인한다. 원본 내부 시작점은 사용할 수 있지만 경로·구간·이유를 기록한다. |
| 같은 소스 분할 | 연속된 동일 소스의 기술적 분할은 하나의 논리 컷으로 취급한다. 짧은 표시 자막마다 영상을 다시 자르지 않는다. |
| 클린본 길이 부족 | 원속으로 가능한 길이까지만 배치하고 해당 의미 섹션의 남은 꼬리만 선언된 공백으로 둔다. 다음 컷은 원래 섹션 시작에 둔다. 루프·정지·배속·임의 대체는 금지한다. 공백은 결과에 표시한다. |
| 영상 트랙 | 동시 화면이 필요하지 않으면 메인 영상 트랙 하나를 쓴다. 동일 영상을 중복 트랙으로 쌓지 않는다. |

## 자막을 포함할 때만 적용

- **문구:** 실제 발화한 내용만 사용한다. 원래 단어·의미·순서를 보존하며 본문 자막 끝의 마침표 `.`, `．`, `。`는 제거한다.
- **분할:** 실제 폰트로 한 줄에 들어가는 폭과 한국어 문법을 함께 본다. 조사·수식어·끝 한 음절만 남기는 분할은 금지한다. 표시 자막을 나눠도 같은 의미 섹션의 영상은 유지한다.
- **타이밍:** 모든 자막의 시작을 위 발음 시작 판단으로 개별 확인한다. 영상 컷에 붙은 첫 자막뿐 아니라 문장 안의 표시 자막도 실제 첫 발음에서 바뀌어야 한다. 각 완성 영상 구간 안에서 이전 자막의 끝을 다음 자막 시작과 같은 프레임에 두어 공백·겹침을 0프레임으로 맞춘다. 마지막 자막은 해당 영상 구간 끝까지만 둔다. 서로 다른 편집안 사이의 의도적 공백은 잇지 않는다.
- **영상과의 관계:** 새 의미 섹션 첫 자막과 incoming 영상 컷의 시작 오차는 0프레임이다. 한 줄 폭 때문에 나눈 내부 자막에는 새 영상 컷을 만들지 않는다.
- **수동 기준:** 사용자가 같은 자막을 둘로 잘라 발음 시작 위치를 표시했다면 그 표시의 의도를 읽고 해당 원본 음성 위치를 반영한다. 표시용 중복을 새 자막 두 개로 남기지 않는다. 앞의 쉼을 줄여 시각이 바뀌면 같은 소리 위치를 추적하며 옛 타임코드를 그대로 붙이지 않는다.
- **기본 디자인:** 새 자막은 Pretendard SemiBold, 흰 글자, 불투명 검은 배경, 한 줄·중앙 정렬이다. 1080×1920 기준 크기 13, X=0/Y=-400을 쓴다. 화면비가 다르면 화면을 바꾸지 말고 해당 화면의 안전 영역에 맞춘다. 기존 자막을 싱크만 고치는 작업에서는 문구·폰트·디자인을 유지한다.
- **자막 제외 요청:** 새 자막을 만들지 않는다. 이미 들어 있는 자막을 삭제하라는 뜻으로 해석하지 않는다.

## 작업 순서와 완료 기준

1. 원본·기존 타임라인을 읽기 전용으로 확인하고, 사용할 구간과 삭제 이유를 정리한다.
2. 음성 컷편집 후 완성 음성을 다시 분석해 문장·의미구 사이에 불필요하게 긴 쉼이 남았는지 확인한다. 남긴 긴 쉼은 의도·발화 보호 등의 이유를 기록한다. 무음 편집을 확정한 최종 음성으로 모든 자막의 실제 첫 발음과 의미 영상 컷을 함께 맞춘다. 파형·필요한 스펙트럼·문맥으로 작은 자음과 호흡을 구분한다. 음성이 바뀌면 다시 분석하고 예전 시간을 비례 환산하지 않는다.
3. 실제 저장이 요청되면 [실행 연결](references/execution.md)을 읽고 대상이 고정된 안전 실행 경로부터 확인한다. 현재 경로가 지원하지 않는 작업을 하위 명령으로 우회하지 않는다.
4. 정확한 기존 업체 프로젝트 안에 **새 편집 가능한 타임라인 1개**만 만든다. 원본·기존 타임라인은 유지한다. CapCut이 켜져 있으면 아래 절차로 현재 작업을 저장하고 정상 종료한 뒤 계속한다. 사용자에게 CapCut 종료나 종료 승인을 요청하지 않는다. 실행 중인 프로젝트에 직접 쓰거나 강제 종료하지 않는다.
5. 저장본을 다시 읽어 구간·싱크·소스·기존 파일 보존을 검증한다. 경계가 서로 같은 프레임이라는 검사와 그 경계가 실제 발음 시작에 맞는다는 검토를 모두 수행한다. 최종 전사에서 누락이 의심되면 해당 원본·최종 구간의 파형과 구간 전사를 재검토하며 문구를 임의 삭제하거나 인식 결과에 맞춰 발음을 자르지 않는다. MP4나 계획 파일만으로 편집 완료라고 하지 않는다.
6. 결과는 새 타임라인 위치, 원본/편집 길이, 삭제 이유, 남은 문제만 간단히 보고한다. 실제 재생·청취·내보내기를 하지 않았다면 했다고 말하지 않는다.

## 실행 중인 CapCut의 자동 저장·정상 종료

사용자가 승인한 공통 절차다. 실제 편집·저장이 요청된 작업에 적용하며 설명·진단만 요청받았을 때는 앱을 종료하지 않는다.

- 준비와 검증은 프로젝트 밖에서 먼저 마친다. 실제 반영 직전에 CapCut이 실행 중이면 **현재 열려 있는 작업을 저장 → 정상 종료 → 종료·잠금 해제 확인 → 편집 반영**을 직접 처리한다. 대상과 다른 프로젝트가 열려 있어도 현재 작업부터 보존하며 다른 프로젝트를 편집 대상으로 바꾸지 않는다.
- 저장과 정상 종료에 필요한 최소한의 앱 제어는 백그라운드 편집 원칙의 명시적 예외다. 현재 제공되는 앱 도구로 실제 메뉴·저장 상태를 확인한다. 고정 좌표나 미확인 단축키를 쓰지 않는다.
- 저장 명령이 있으면 실행하고 완료를 확인한다. 자동 저장 방식이면 저장 완료 표시와 해당 저장 파일을 확인한 뒤 앱의 정상 종료 명령을 쓴다. 종료 중 저장 확인창이 나오면 저장을 선택한다. 변경 사항 버리기·저장 안 함은 선택하지 않는다.
- 앱 프로세스 종료와 대상 프로젝트 잠금 해제를 모두 확인하기 전에는 프로젝트 파일에 직접 쓰지 않는다. 정상 종료 후 최신 원본·타임라인을 다시 읽는다. 준비 이후 사용자의 편집이 바뀌었다면 최신 수동 편집을 반영해 준비본을 갱신하며 이전 상태로 덮어쓰지 않는다.
- **사용자에게 CapCut을 종료해 달라거나 종료해도 되는지 다시 묻지 않는다.** 저장·정상 종료가 오류나 도구 접근 제한으로 실패하면 현재 앱과 작업을 보존하고 구체적인 실패 상태만 보고한다. 강제 종료·잠금 삭제·보안 권한 변경으로 우회하지 않는다.
- 저장이 끝난 뒤 CapCut 재실행·재생·내보내기를 자동으로 추가하지 않는다. 실제로 확인한 저장·종료·등록 상태와 미수행 재생 검증을 구분한다.
