# 공유받은 환경에서 실행하기

`PLUGIN_ROOT`는 현재 읽고 있는 플러그인 안의 `.codex-plugin/plugin.json`이 있는 폴더다. 설치 캐시 버전이나 작성자의 사용자 이름을 고정하지 않는다. 쉘 명령에는 확인한 절대 경로를 인용하여 사용한다.

제품 자료 기본 경로는 수신자의 `~/Documents/인코어`다. 다른 폴더를 쓰면 해당 실행의 `VIDEO_PRODUCT_LIBRARY_ROOT` 환경변수와 `--root` 지원 인자에 동일한 절대 경로를 전달한다. 업체와 제품은 사용자가 지정해야 하며, 폴더가 없다고 다른 업체 자료를 가져오지 않는다. 제품 자료와 API 키, 음성 복제 ID, 과거 작업물은 공유 패키지에 포함하지 않는다.

Python 패키지는 `python3 "$PLUGIN_ROOT/scripts/setup_runtime.py"`로 수신자 전용 가상환경에 설치한다. 이후 실행에는 `~/.local/share/ai-video-reference-replication/venv/bin/python`을 사용한다.

먼저 `python3 "$PLUGIN_ROOT/scripts/doctor.py"`로 로컬 도구를 읽기 전용 확인한다. 이 검사는 서비스 로그인이나 실제 유료 생성 성공을 증명하지 않는다. 선택한 제작 단계에 필요한 조건만 확인한다.

- 이미지: Codex 내장 `image_gen`과 시스템 `imagegen` 스킬이 필요하다. 다른 이미지 API로 대체하지 않는다.
- AI 영상: 수신자 자신의 Higgsfield 연결과 Kling v3.0 이용 권한이 필요하다. 패키지는 인증값이나 MCP 설정을 복사하지 않는다. 사용 가능한 도구와 반환 모델을 제작 시 확인한다.
- TTS: 수신자 자신의 ElevenLabs 계정과 지원 스킬의 인증 경로를 사용한다. 환경변수의 값이나 인증 파일 내용을 채팅에 출력하지 않는다. 과거 소유자의 음성·설정을 추정하지 않는다.
- 기본 9:16 의미별 편집: 포함된 `capcut-semantic-cut-edit`의 실행 코드와 수신자의 기존 CapCut 프로젝트를 사용한다. 현재 구현은 macOS 기준이다. 원본 프로젝트를 보존하고 새 타임라인을 검증해야 한다.
- 별도 스타일·엄격한 복제·범용 편집: `CAPCUT_AUTOMATION_ROOT`로 지정한 별도 CapCut 자동화 실행 엔진이 필요하다. 이 패키지에 소유자의 실행 프로젝트나 학습 데이터는 들어 있지 않다. 엔진이 없으면 해당 단계가 미구성임을 알리고 완료로 표시하지 않는다.
- Windows: 플러그인 문서 설치와 제작 기획은 가능하지만 `fcntl`, macOS CapCut 경로·앱 제어에 의존하는 실행은 Windows 이식·검증 전까지 지원한다고 표시하지 않는다.

지원 스킬을 읽을 때 같은 플러그인의 `skills/<이름>/SKILL.md`를 우선한다. `ai-video-reference-tts-workflow`는 별도 통합 워크플로에 대한 선택적 안내다. 본 플러그인의 직접 TTS 경로에는 필요 없으며 없을 때 그 별도 경로를 시작하지 않는다. `product-page-reference-video`는 상위 계약이 허용한 제품 분석 단계까지만 사용한다. 내장 OpenAI 이미지 전용·Kling v3.0 고정·기존 클린본 모드 생성 금지는 모든 하위 안내보다 우선한다.

받는 사람의 설정·제품 파일은 설치 폴더 밖에 둔다. 새 버전 설치가 사용자 자료를 덮어쓰면 안 된다. 실제 미설치 도구나 필수 입력이 없는 경우에만 해당 항목을 짧게 안내한다.
